# 路线图

**当前阶段：完善与优化。** 框架已经建完，不再按里程碑推进新范围。

工作项只有两个来源：[DEBT.md](DEBT.md) 的台账，和下面的能力欠账。
两者的区别是——台账修的是**已经声称做完但没做实**的东西，能力欠账是**还没开始做**的东西。
**先还账，再添新功能**：在承诺没兑现的地基上加东西，只会让台账变长。

## 现在做什么

### 第一优先：还账

排序与理由见 [DEBT.md](DEBT.md) 的「优先级建议」。摘要：

| 顺序 | 事项                                     | 为什么排这里                                     |
| ---- | ---------------------------------------- | ------------------------------------------------ |
| 2    | worktree 不清理（B-4）                   | 唯一一条在用户磁盘上持续累积的                   |
| 3    | **三条接缝守卫**（B-6 / B-5 / B-2）      | 这三条是**成因**。不补，前面几条会以新形态长出来 |
| 4    | 事件发射补齐（B-2）                      | 违反架构第一原则「RunEvent 是唯一事实来源」      |
| 5    | 提示词库接上执行路径（B-3）              | 一整屏功能没有出口                               |

`notify` 那条（原 B-1）已经还清：接上了 `tauri-plugin-notification`、
capabilities 逐条授权、发 `system.notification_sent` 事件、
发不出去时走 `failed` 端口并把原因写进事件。

第 4 项值得单独说。契约能声明三样东西——节点类型、配置字段、事件类型——
**三样都有「声明了但没人实现」的情况，而三样都没有守卫**。
补三条同构的守卫测试，比逐条修实现更值：它们会把台账里大半条目
变成「会自己红的东西」，而不是靠人记得。

### 第二优先：能力欠账

这些是**还没开始做**的，不在台账里。

| 事项                                       | 说明                                                                   |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| **`branch` 节点**                          | 没有条件分支，工作流表达力有个洞。优先级最高的一个节点类型             |
| **`mcp.tool` 节点**                        | 把整个应用开成了 50 工具的 MCP Server，工作流自己却调不了 MCP 工具     |
| **`subworkflow` 节点**                     | 地基已在（`parent_run_id` 建表就有、契约有 `parentRunId`），引擎零引用 |
| `script.python` / `transform` / `env` 节点 | 补齐，工作量小                                                         |
| **WKWebView 性能基准**                     | 至今零测试。「拖动卡」是唯一一条真实用户反馈，定论依赖它               |
| 模型策略映射                               | 要等 `provider.api`（HTTPS 直连）运行时——ACP adapter 不接受模型参数    |

### 不做的

| 事项          | 理由                                                                                                                                                      |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `env.install` | 应用自己不下载任何东西。替用户下载解压就要为「从哪下、怎么验签、装坏了怎么回滚」全都做决定，每个决定都是新的攻击面。契约里那个方法建议删掉或标 deprecated |
| Apple 公证    | 内部分发，不买 Developer ID。绕过而不是满足那一层，见 [RELEASE.md](RELEASE.md)                                                                            |

## 长期

### Web 形态

现状：只有 `MemoryTransport`（返回空数组）与 `crates/devserver`（179 行、无鉴权、
自称「只用于本地开发与端到端测试」）。tRPC / SSE / Web Push / 服务端凭据都没有。

**开工前先回答一个产品问题：Web 形态给谁用。**
如果定位确实是「只读与审批场景优先」，那么把 63 个方法全量搬上 tRPC 是过度设计——
只做「观测 + 审批 + Web Push」三件事的窄接口会快得多，鉴权也更容易做对。

## 已知风险

| 风险                                  | 缓解                                                                         |
| ------------------------------------- | ---------------------------------------------------------------------------- |
| ACP Adapter 版本漂移导致 Session 失效 | 启动时跑兼容性探针；不可恢复时明确告知「已用结构化状态重建」                 |
| WKWebView 与 Chromium 行为差异        | 见上方「WKWebView 性能基准」——目前**没有**缓解，只有风险                     |
| 大 Run 事件量膨胀                     | 事件只存摘要与引用，日志分块 + 上限截断                                      |
| 应用未经 Apple 公证                   | `scripts/install-app.sh` 清除隔离标记；CI 已留好签名分支，配齐 Secret 即启用 |
