## M2 · 执行态 ✅

**范围**：Rust 引擎、脚本与 worktree 节点、RunEvent 事件流、启动表单与 Dry Run、并行 / 汇聚调度、审批与检查点、执行记录三级视图。

**出口标准**：杀掉 App 后重启能回到同一审批点；同一工作流不同参数并行运行互不影响；事件流可完整回放。

已交付（Rust 143 项测试 + 前端 457 项）：

- [x] **执行计划**：拓扑排序 + ready_nodes，支持 All / Any / Quorum / Sequential 四种汇聚
- [x] **脚本节点**：真起进程、真超时（sleep 30 在 300ms 内被中断）、stdout/stderr 并发读
      （只读一个会在输出量大时死锁）、1MB 输出上限
- [x] **Git worktree 节点**：分支已存在拒绝复用、有未提交改动拒绝清理、
      分支名斜杠转短横（避免清理时误删同级 worktree）
- [x] **变量插值**：`${input.*}` / `${run.*}` / `${节点.端口[.路径]}`；
      未解析的引用是硬错误；尾部换行去掉，与 shell 的 `$(...)` 一致
- [x] **审批与检查点**：审批是引擎强制的暂停点（执行器无法绕过）；
      每个节点完成后落一次带 Scope 快照的检查点
- [x] **后台运行管理器**：每个运行一个线程 + 一条 SQLite 连接；
      挂在审批上的运行不占执行槽；取消在节点边界生效
- [x] **产物存储**：大 payload 落 artifacts/，事件只留摘要；路径逃逸有测试压着
- [x] **Dry Run 依赖检查**：只列真的查过的项，包括「尚未实现的节点类型」
- [x] **执行记录三栏**（图纸「03 执行记录」）：运行列表 · 节点进度 · 详情三 tab
- [x] **启动表单**（图纸 660px 对话框）：字段由入口节点的输入 Schema 生成

出口标准逐条验证（`crates/engine/tests/supervisor_test.rs`）：

| 出口标准                   | 验证方式                                                                   |
| -------------------------- | -------------------------------------------------------------------------- |
| 杀掉 App 后回到同一审批点  | drop 全部内存对象后重开数据库，批准并跑完，断言上游输出跨重启存活          |
| 同一工作流并行运行互不影响 | 真并发两个运行，各自写自己工作目录的文件，内容是各自的 run id              |
| 事件流可完整回放           | seq 从 1 逐条连续无缺口，生命周期事件齐全，每个节点 started/succeeded 配对 |

**留给 M3 的**：AI 四类节点（`ai.analyze` / `ai.execute` / `ai.review` / `ai.decide`）
在 Dry Run 阶段就明确报「尚未实现」，不会假装成功。执行记录的「对话」tab
同样是空态加说明。

## M3 · AI 能力 ✅

**范围**：ACP Adapter（Claude Code / Codex）、分析 / 审查 / 决策 / 执行四类节点、Agent 角色、提示词库、模型登记与策略映射。

已交付：

- [x] **模型登记**（图纸「07 模型」）：凭据只接受 `keychain://` 引用，
      明文在存储层就被拒绝；「所有下拉只列已启用条目」在存储层实现，不靠调用方自觉
- [x] **Agent 角色**（图纸「05 Agent 角色」）：角色被引用而非复制，
      保存即新版本；内置角色不可删只可复制
- [x] **提示词库**（图纸「06 提示词库」）：分段可见可改、变量表、版本；
      存储层拒收空分段
- [x] **ACP Adapter**：Rust 直连 adapter（ADR 0002），协议形状取自实测
- [x] **AI 四类节点**：analyze / execute / review / decide 走真实 ACP 会话

实证记录（`tests/e2e/acp-real.mjs`，装了 adapter 才跑）：

| 断言                                                     | 结果 |
| -------------------------------------------------------- | ---- |
| 握手返回 protocolVersion 1 + agentCapabilities           | ✅   |
| **握手不返回模型列表** —— 印证「模型要单独登记」这个设计 | ✅   |
| session/new 返回权限档位（modes）                        | ✅   |
| 收到 session/update 流式通知                             | ✅   |

补齐（原先漏在「已交付」里的两处）：

- [x] **提示词的版本历史**：图纸的版本页列的是 v4 · 当前 / v3 / v2，
      每条带「时间 · 谁改的」。之前只有当前版本一行，而那一页底部写着
      「历史结果始终可解释」—— 历史都看不到，那句话就是空的
- [x] **插入变量 / 添加分段**：图纸的变量表本来就没有「添加」按钮 ——
      变量是写在正文里的占位符，表格只是列出它们。答案是每段标题旁的
      「插入变量」，点它插入正确写法
- [x] **测试连通性**（图纸「07 模型」）：只做握手 + 建会话，不发提示词 ——
      那样快、不花钱，而且已经足以回答「这个模型现在能不能用」。
      adapter 没装走 ok=false 而不是报错：那是最常见的情况，
      用户需要的是「装什么」

**留给后续的**：模型策略映射（Agent 选「策略」时解析到具体模型）。

**不提前做的理由**：ACP adapter 不接受模型参数 —— 模型由 CLI 自己的配置
决定，所以策略映射在当前架构下**没有执行侧的落点**。它要等 `provider.api`
（HTTPS 直连）运行时，那时「选哪个模型」才真的成立。
只做界面的话，又是一处「界面上承诺了却不存在」。

**出口标准**：端到端跑通 Issue → 分析 → 审批 → worktree → 执行 → 审查 → 决策 → PR；提示词与模型在运行记录中可追溯到具体版本。

⚠️ 接入前先跑 `docs/reference/acp/reference/probe.ts`：那份经验里 codex 侧只在旧版本验证过，
「某能力不支持」的结论会过期。

## M4 · 主管 AI 与记忆 ✅

**范围**：MCP Server（只读 + create / patch / validate + 记忆 CRUD）、主管 AI 抽屉与历史会话、结构化 Patch 与可视化 Diff、记忆五作用域与提议写入。

**出口标准**：用自然语言完成一次「插入节点并改接连线」，Diff 确认后写入草稿且 baseRevision 守卫生效；记忆注入可在事件中溯源。

已交付：

- [x] **MCP Server 能被真实客户端连上**：stdio 协议层（JSON-RPC over
      newline-delimited JSON）+ 可执行入口，实测 16 个工具、读到 886 条真实工作流、
      未暴露的工具被拒。见 [MCP.md](MCP.md)
- [x] **主管 AI 的改动先出 Diff**：回答里带结构化 proposal，界面算出 Diff 供确认，
      确认后才走 workflow.patch（那里有 baseRevision 守卫）。
      从自然语言里抠 JSON 是最脆的一环，9 条测试压着
- [x] 上下文接通：草稿 rev、选中节点数、当前工作流从编辑器状态直接读
- [x] 记忆五作用域与提议写入（界面 + 存储层）

- [x] **历史会话**：会话与消息落库，可展开、可恢复、续接同一条。
      消息按 seq 排而不是按时间 —— 同一秒写两条时按时间排的顺序不稳定，
      而对话读起来颠倒就完全没法理解
- [x] **记忆注入可在事件中溯源**（出口标准的后半句）：AI 节点真的注入记忆，
      运行开始时取一次快照并写 `system.memory_injected`。
      在**取快照时**就写而不是等某个 AI 节点跑完 —— 那个节点可能失败、
      可能被取消，而「这次运行带着这些记忆」在它开始前就已经成立
- [x] MCP 的写工具默认关闭：只读会话只给只读工具。
      这个进程弹不出应用里的确认对话框，而「改动先出 Diff」是核心规则

- [x] **MCP 的写确认接通**：跨进程信箱（`mcp_confirmation` 表）——
      MCP 提交待确认 → 应用轮询到并弹确认卡 → 用户决定 → MCP 侧读到结果。
      写工具因此**默认开放**了，但每一次写都要人点头。
      三条安全默认：出错不放行、超时（180 秒）不放行、决定只能做一次。
      `mcp.pendingConfirms` 与 `mcp.decideConfirm` 的 Scope 是 null ——
      给远端就等于让 MCP 自己批准自己。
      实测：真实 MCP 进程调 workflow.create 会挂起，批准后返回真实 id

## M5 · 可交付

**范围**：首次配置引导与工具安装、环境健康中心、通知与恢复、子工作流编排、失败重试与诊断包导出、签名公证与更新通道。

**出口标准**：全新设备一键安装后 10 分钟内跑完内置示例；失败可从失败节点重试；诊断包不含 Secret。

已交付：

- [x] 自动发布流水线、应用内一键更新（见 [RELEASE.md](RELEASE.md)）
- [x] **失败可从失败节点重试**（出口标准的一条）：引擎侧 resume 从事件流算出
      哪些节点已完成，成功的不重跑；界面给出「从失败节点重试」与「用相同参数重跑」
- [x] **环境健康中心**：每项能力的版本、路径、来源与状态，可重新检查。
      只做检测那一半，而且只读
- [x] **诊断包不含 Secret**（出口标准的一条）：三道脱敏（事件逐条、启动参数、
      整段再扫一遍），产物只列元信息不含内容。环境诊断（`env.diagnostics`）
      走同一个 Redactor —— 首次配置与设置两屏都没有 runId，用不了 run.diagnostics
- [x] **首次配置的四步与检测**：图纸底部的三个按钮都在，「确认并安装」这一档
      按已确认的偏离改成只检测、给可复制的命令。工作目录与权限档会真的落库
      （`workspace_setting`），顶栏与侧栏据此显示 —— 在此之前那三处没有数据源，
      界面上悬着「尚未授权 / 未设置 / 未检查」而应用里没有东西能改掉它们

剩余：

- [ ] Apple 证书签名公证
- [x] **设置屏的分组导航与权限策略三档**：图纸「05 设置与环境」的左边 184px
      八个分组 + 右边三张权限卡。**引擎真的按档位办事**：
      `review_every_change` 下有副作用的节点（脚本、worktree、commit、PR、
      MCP 工具）执行前挂起等审批，批准过的恢复时不再重复问。
      实测同一条工作流：严格档停在 Shell 节点（`waiting_approval`），
      宽松档直接跑完（`succeeded`）。
      没设过按最严的办 —— 默认放宽等于替用户做了一个他不知道的决定
- [x] **「将执行的命令」逐条列出**（图纸的要求）：点「确认并安装（N 项）」
      展开命令清单，每条带出处，另给一键脚本 `scripts/install-deps.sh`。
      **`env.install` 不实现** —— 应用自己不下载任何东西：替用户执行下载
      与解压，就要为「从哪下载、怎么校验签名、装坏了怎么回滚」全都做决定，
      而每个决定都是新的攻击面。契约里那个方法留着（图纸的能力），
      但没有实现，也没有接线

## 已知风险

来自技术选型 §9，加上施工中发现的：

| 风险                                  | 缓解                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| ACP Adapter 版本漂移导致 Session 失效 | 启动时跑兼容性探针；不可恢复时明确告知「已用结构化状态重建」，不伪装连续      |
| WKWebView 与 Chromium 行为差异        | 画布与虚拟化在两端各跑基准；CI 加 Safari Tech Preview 冒烟                    |
| 大 Run 事件量膨胀                     | 事件只存摘要与引用，日志分块 + 上限截断，保留策略可配置                       |
| Rust 人手                             | 契约已冻结，引擎可先用 Node 原型跑通再迁移；IPC 契约不变                      |
| 应用未经 Apple 公证                   | 首次打开需右键；拿到开发者证书后 CI 会自动启用签名公证（workflow 已留好分支） |
