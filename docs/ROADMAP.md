## M2 · 执行态 ✅

**范围**：Rust 引擎、脚本与 worktree 节点、RunEvent 事件流、启动表单与 Dry Run、并行 / 汇聚调度、审批与检查点、执行记录三级视图。

**出口标准**：杀掉 App 后重启能回到同一审批点；同一工作流不同参数并行运行互不影响；事件流可完整回放。

已交付（Rust 143 项测试 + 前端 457 项）：

- [x] **执行计划**：拓扑排序 + ready_nodes，支持 All / Any / Quorum / Sequential 四种汇聚
- [x] **脚本节点**：真起进程、真超时（sleep 30 在 300ms 内被中断）、stdout/stderr 并发读
      （只读一个会在输出量大时死锁）、1MB 输出上限
- [x] **Git worktree 节点**：分支已存在拒绝复用、有未提交改动拒绝清理、
      分支名斜杠转短横（避免清理时误删同级 worktree）
- [x] **变量插值**：`${input.*}` / `${run.*}` / `${节点.端口[.路径]}`；
      未解析的引用是硬错误；尾部换行去掉，与 shell 的 `$(...)` 一致
- [x] **审批与检查点**：审批是引擎强制的暂停点（执行器无法绕过）；
      每个节点完成后落一次带 Scope 快照的检查点
- [x] **后台运行管理器**：每个运行一个线程 + 一条 SQLite 连接；
      挂在审批上的运行不占执行槽；取消在节点边界生效
- [x] **产物存储**：大 payload 落 artifacts/，事件只留摘要；路径逃逸有测试压着
- [x] **Dry Run 依赖检查**：只列真的查过的项，包括「尚未实现的节点类型」
- [x] **执行记录三栏**（图纸「03 执行记录」）：运行列表 · 节点进度 · 详情三 tab
- [x] **启动表单**（图纸 660px 对话框）：字段由入口节点的输入 Schema 生成

出口标准逐条验证（`crates/engine/tests/supervisor_test.rs`）：

| 出口标准                   | 验证方式                                                                   |
| -------------------------- | -------------------------------------------------------------------------- |
| 杀掉 App 后回到同一审批点  | drop 全部内存对象后重开数据库，批准并跑完，断言上游输出跨重启存活          |
| 同一工作流并行运行互不影响 | 真并发两个运行，各自写自己工作目录的文件，内容是各自的 run id              |
| 事件流可完整回放           | seq 从 1 逐条连续无缺口，生命周期事件齐全，每个节点 started/succeeded 配对 |

**留给 M3 的**：AI 四类节点（`ai.analyze` / `ai.execute` / `ai.review` / `ai.decide`）
在 Dry Run 阶段就明确报「尚未实现」，不会假装成功。执行记录的「对话」tab
同样是空态加说明。

## M3 · AI 能力

**范围**：ACP Adapter（Claude Code / Codex）、分析 / 审查 / 决策 / 执行四类节点、Agent 角色、提示词库、模型登记与策略映射。

**出口标准**：端到端跑通 Issue → 分析 → 审批 → worktree → 执行 → 审查 → 决策 → PR；提示词与模型在运行记录中可追溯到具体版本。

⚠️ 接入前先跑 `docs/reference/acp/reference/probe.ts`：那份经验里 codex 侧只在旧版本验证过，
「某能力不支持」的结论会过期。

## M4 · 主管 AI 与记忆

**范围**：MCP Server（只读 + create / patch / validate + 记忆 CRUD）、主管 AI 抽屉与历史会话、结构化 Patch 与可视化 Diff、记忆五作用域与提议写入。

**出口标准**：用自然语言完成一次「插入节点并改接连线」，Diff 确认后写入草稿且 baseRevision 守卫生效；记忆注入可在事件中溯源。

## M5 · 可交付

**范围**：首次配置引导与工具安装、环境健康中心、通知与恢复、子工作流编排、失败重试与诊断包导出、签名公证与更新通道。

## M6 · Web 形态

**出口标准**：浏览器端可观测运行、处理审批；不承诺纯浏览器执行本地命令。

已提前完成：应用外壳、路由、传输抽象（`Transport` 接口两端同形）。

## 已知风险

来自技术选型 §9，加上施工中发现的：

| 风险                                  | 缓解                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| ACP Adapter 版本漂移导致 Session 失效 | 启动时跑兼容性探针；不可恢复时明确告知「已用结构化状态重建」，不伪装连续      |
| WKWebView 与 Chromium 行为差异        | 画布与虚拟化在两端各跑基准；CI 加 Safari Tech Preview 冒烟                    |
| 大 Run 事件量膨胀                     | 事件只存摘要与引用，日志分块 + 上限截断，保留策略可配置                       |
| Rust 人手                             | 契约已冻结，引擎可先用 Node 原型跑通再迁移；IPC 契约不变                      |
| 应用未经 Apple 公证                   | 首次打开需右键；拿到开发者证书后 CI 会自动启用签名公证（workflow 已留好分支） |
