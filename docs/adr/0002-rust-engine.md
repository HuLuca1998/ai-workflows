# ADR-0002：编排引擎用 Rust

- 状态：已采纳
- 日期：2026-07-27

## 背景

引擎要做：调度与并行分发、检查点、环境快照、路径 canonicalize、子进程隔离、脱敏。
这些都在「出问题时用户察觉不到」的那一类——路径守卫漏一个符号链接，界面照样正常。

## 决策

调度、检查点、`PathGuard`、`Redactor` 全部在 Rust 进程内完成，**不经过 JS**。

## 理由

- 安全边界应该只有一层。如果路径校验在 JS、执行在 Rust，两边对「什么是同一个路径」
  的理解稍有差异就是一个漏洞
- 子进程管理、超时、输出上限截断在 Rust 里更可控
- 类型系统能把「状态机不允许的迁移」表达成编译期约束

## 代价

- 需要 Rust 人手。缓解：契约已冻结，引擎可先用 Node 原型跑通契约，M2 再迁移，IPC 契约不变
- 迭代速度比 TS 慢

## 现状

M0 已落地 `PathGuard`（17 项逃逸用例）、`Redactor`（13 项）、状态机与存储层。
调度器在 M2。
