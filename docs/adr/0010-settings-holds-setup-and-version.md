# ADR-0010：主导航放日常，设置放配置——首次配置与系统版本归入设置

- 状态：已采纳
- 日期：2026-07-29
- 影响：图纸 `AI Workflows 客户端.dc.html` 的主导航与「05 设置与环境」屏

## 背景

CLAUDE.md 第一条纪律是「UI 严格按图纸施工」。这条 ADR 记的是一次
**产品负责人明确授权的偏离**（原话：「你好好规划一下菜单，不用再死跟模板」），
以及规划的依据。

触发它的是一个具体问题：更新入口找不到。原先的位置是

    设置与环境 → 运行环境与工具 → 滚到底 → 第三块卡片

前面挡着环境健康表（8 行能力清单，每行带路径与安装命令）和权限策略
三张卡。1440×900 的窗口要滚过整整一屏才看得到「检查更新」。

这对一般功能只是不方便，对更新入口不是。这个应用**装在用户本地、
靠自更新分发**（ADR-0006）：没有服务端能强推版本，又刻意不做
「发现新版本就弹窗」（UpdateCard 的注释写着理由：这是会长时间挂着
运行的工具，打断正在等审批的用户代价更大）。于是「用户主动来看」
是新版本到达他机器的**唯一路径**，而这条路径埋在三层之下。

顺带查出来的：托盘菜单「检查更新…」点了 `emit("navigate", ...)`，
而 web 侧**没有任何地方监听 `navigate` 事件**。那一项一直是死的，
点了只会把窗口调出来停在原处。第二条路径也是断的。

## 决策

信息架构按**一条线**划分：

> 主导航放**每天都要用的**，设置放**配置与一次性的**。

### 主导航（8 → 7 项 + 设置）

    概览与工作流 · 工作流编辑器 · 执行记录
    记忆 · Agent 角色 · 提示词库 · 模型
    设置与环境

「首次配置」撤出。它是装机时走一遍、之后不再进的东西，
常驻主导航占的是一个用户每天都要扫过的位置。
`/onboarding` 路由**保留** —— 首次启动仍要能直达，
文档与收藏里的旧链接也不该断。

### 设置（8 → 10 档）

    首次配置          ← 新，置顶
    通用
    AI 与 Agent
    Git 与 GitHub
    运行环境与工具
    MCP 与集成
    通知
    安全与隐私
    高级              ← 一键初始化在这里
    系统版本          ← 新，置底

顺序不是照图纸抄的，是按**什么时候会用到**排：

- **装机**（首次配置）→ 只走一遍，所以在最上面，装完就往下走
- **日常配置**（通用 … 安全与隐私）→ 图纸那八档，顺序原样不动
- **少碰的**（高级、系统版本）→ 需要时找得到就行

首次配置与「运行环境与工具」相邻是有意的：它们本就是同一件事的
两个阶段（装依赖 / 看依赖健康），隔在两个不同的地方反而难对照。

### 顺带修好的

- `apps/web/src/layout/useTrayNavigation.ts` 接上 `navigate` 事件
- 桌面壳 emit 的目标改成 `/settings?tab=version` ——
  只跳 `/settings` 会停在默认档，用户还得自己在左栏找，等于没跳
- `SettingsPage` 支持 `?tab=` 定位，认不出的值忽略
  （URL 是用户能手改的，一个错字不该打出空白页）

## 为什么不是别的方案

| 方案                           | 为什么没选                                                                      |
| ------------------------------ | ------------------------------------------------------------------------------- |
| 系统版本在主导航单独一项       | 试过（本 ADR 的第一版）。它一年用不到几次，却占了一个日常位置 —— 与首次配置同病 |
| macOS 菜单栏「关于」           | Web 形态没有菜单栏，那边完全看不到；而 Web 形态也要能知道自己是什么版本         |
| 保持原位，只把版本卡片挪到最上 | 治标：环境健康表往后一长，它又被挤下去了。位置靠内容长度决定就不算有位置        |

## 代价

- 图纸的主导航与实现不再一致（少「首次配置」），设置左栏多两档。
  `apps/web/src/navigation.ts` 与 `SettingsPage.tsx` 里都有指回这份
  ADR 的注释，下次照图纸核对时会撞到。
- 图纸里「06 首次安装与检测」仍是一整屏。实现里它是设置的一档，
  内容一字未改 —— 变的是入口，不是那一屏本身。

## 验证

`apps/web/tests/settings-tabs.test.tsx`：分档顺序（首次配置在最上、
系统版本在最下、中间八档照旧）、两档点开都有真实内容、环境档里不再有
版本卡片、`?tab=version` 直达、认不出的 tab 值不打出空白页、
主导航不含首次配置但 `/onboarding` 路由还在、托盘 emit 的目标带
`?tab=version` 且前端确实接了那个事件。

「找得到」是这次调整的全部理由，所以它必须有测试守着 ——
把版本卡片挪回环境档滚到底、把首次配置排到最后，
现有的功能测试一条都不会红。

## 后记（2026-07-29）

这条 ADR 写的时候，CLAUDE.md 第一条纪律还是「UI 严格按图纸施工」，
所以它花了大量篇幅论证「为什么这次可以偏离」。

**那条纪律已经取消了** —— 框架建完之后进入完善优化阶段，
界面形态以当前实现为准，图纸归档到 `docs/archive/design/`。
所以这条 ADR 里「偏离图纸需要理由」的框架不再适用，
但它记录的**判断依据仍然成立**：菜单按「什么时候会用到」分组，
而不是按图纸的平铺顺序；改动必须有测试守着，否则下次会被滚回去。
