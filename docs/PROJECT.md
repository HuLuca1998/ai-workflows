# 项目定位

**AI Workflows 是一个本地优先的 AI Workflow 客户端。**

它把 AI 能力、脚本、人工审批、Git 隔离、通知与外部服务连成可复用的工作流，
并让一个了解全软件能力的「主管 AI」协助设计、解释、优化与排障。

形态：macOS App（Tauri 2）+ Web（同一引擎的远程界面）。

## 要解决的问题

把一件重复的技术工作（修 Issue、审代码、归因崩溃日志、批量整理文件）拆成一份计划，
交给 AI 执行，但**每一步都能看清、能停下、能接管**。

现有工具的问题是两极：要么全自动但不可解释（出了事只能重来），
要么全手动（AI 只在对话框里给建议，落地还得自己来）。

## 六条产品原则

| 原则             | 含义                                                           | 在代码里的落点                                        |
| ---------------- | -------------------------------------------------------------- | ----------------------------------------------------- |
| 可解释优先       | 任何时刻都能回答「现在跑到哪、为什么停、接下来做什么」         | `RunEvent` 是唯一事实来源；`EventStore.provenance()`  |
| 显式权限         | 文件、命令、网络、Secret 由策略控制，引擎强制，Prompt 无法越权 | `Capabilities`、`PathGuard`、能力声明在节点定义里     |
| 草稿与执行分离   | 编辑草稿不影响运行中的版本                                     | `workflow_revision` / `workflow_version` 两张表       |
| 结构化数据优先   | 节点之间按字段传递，文本拼接只是兼容方式                       | 节点端口的数据形状、`transform` 节点的 JSONPath 映射  |
| AI 建议 ≠ 执行   | AI 的修改一律先出 Diff，用户确认后才写入                       | `DraftStore.propose()` / `acceptProposal()`           |
| 本地优先与可恢复 | 数据留在本机；审批等待、重启、断网不丢 Run                     | SQLite + `run_checkpoint`；`RunStatus.is_resumable()` |

## 范围

**做**：工作流设计（画布 + 16 种节点）、执行引擎（并行 / 汇聚 / 审批 / 检查点）、
AI 节点（分析 / 审查 / 决策 / 执行）、记忆、Agent 角色、提示词库、模型登记、
主管 AI（⌘K）、MCP 出口、环境健康与首次配置、macOS 通知。

**首版不做**：

- 不兼容 Alfred Workflow 文件格式；不做团队云协作与多人实时编辑
- 通知渠道只做 macOS 系统通知，不做 Telegram / Discord
- 不展示模型私有原始思维链，只展示面向用户的推理摘要、工具证据与结果
- 不承诺任意第三方命令自动静默安装；系统级依赖必须告知并授权
- Web 形态不承诺纯浏览器执行本地命令——它是同一引擎的远程界面

## 跨阶段验收标准

任何时候都要满足：

1. 任何运行都能回答：用了哪个版本、哪些提示词版本、哪个模型、注入了哪些记忆、谁在什么时候批准了什么。
2. 所有外部写操作（push / PR / 发布 / 删除）都由审批或决策结果授权，重试前核对外部状态。
3. Secret 从不出现在事件、日志、预览与导出中；界面不提供绕过脱敏的入口。
4. 断电、退出、网络中断后重新打开，未结束的 Run 显示真实状态并可恢复。
5. 深色界面在 Increase Contrast 与 Reduce Motion 下仍可用；重要状态不只用颜色表达；1280×800 窗口下三栏可收起。

每条都有对应的自动化门禁，见 [TESTING.md](TESTING.md)。
