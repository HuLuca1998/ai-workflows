测试时间：2026-07-28 16:27–16:44（Asia/Singapore）

## 第一部分：逐条复测

### 1. 🟡 主管 AI：部分修复，已经会用应用，但仍慢且有一个版本号误导

复现步骤：

1. 在首页点击“询问 AI”。
2. 选择“UI 登记的模型 1785211220166”。
3. 输入“我第一次使用这个应用。请只根据当前应用的界面，用三步告诉我怎样创建、编辑并运行一个最简单的工作流；并说明哪些动作必须由我自己确认。”并发送。
4. 等待回复并计时。
5. 再发送“请用一句话解释这里的工作流是什么。”，1.2 秒后点击“取消”，再等待 1.2 秒。

实际结果：

- 首条请求在 20.1 秒后完成。回复正确说出了“首页新建 → 画布编排入口、执行、结束节点 → 发布并运行”，还明确说明发布与运行必须由用户自己操作，审批节点也需要用户确认。这与第二轮“对这个应用一无所知”相比是实质修复。
- 取消后等待态结束，消息下方留下“等待 1 秒后已取消”，不再像没点过取消。
- 回复仍不够快；简单的首次使用说明要等约 20 秒。
- 回复称“新建后拿到草稿（rev 1）”，但我随后实际新建的空工作流显示 `草稿 · rev0`。主路径是对的，细节仍会误导首次用户。

判断：应用上下文和取消回执已修复；响应速度与细节准确性只到“能用但别扭”。

### 2. 模型下拉：已修复

复现步骤：

1. 进入“模型”，记录第一页 50 条的启停状态。
2. 点击“下一页”，记录第二页 26 条的启停状态，并确认三条基线模型存在。
3. 返回首页打开“询问 AI”，展开“切换模型”下拉，统计选项并检查三条基线模型。

实际结果：模型页第一页 48 条启用、2 条停用，第二页 23 条启用、3 条停用，共 71 条启用；主管 AI 下拉正好 71 项。`[基线] Codex · high`、`[基线] Sonnet 5 · medium`、`[基线] Opus 5 · high` 都在下拉中。

判断：上一轮“只列前 50 条”的分页回归已经闭环。

### 3. 🟡 空草稿立即落库：仍存在

复现步骤：

1. 首页点击“新建工作流”。
2. 不改名、不拖节点、不点保存，观察标题、版本和保存状态。
3. 用只读 SQLite 按 URL 中的 ID 查询 `workflow` 表。

实际结果：进入 `http://localhost:5173/editor/wf_92462438f7614d4e` 后立即显示“未命名工作流 1294 / 草稿 · rev0 / 已保存 / 0 节点 0 连接”。数据库中已有：

```text
wf_92462438f7614d4e|未命名工作流 1294|2026-07-28T08:41:59.433Z|2026-07-28T08:41:59.433Z|0
```

判断：行为与第二轮相同。上一轮处理说明已经给出保留它的工程理由，因此这里记录“仍存在”，不把它当成新回归。

### 4. 🟡 提示词变量：部分修复，能识别占位符但仍不能完成登记

复现步骤：

1. 进入“提示词库”，搜索并打开“Codex Round 2 提示词 1785222114277”。
2. 打开“变量”页，观察空状态说明。
3. 回到“模板”，点击 ROLE 旁的“插入变量”，随后直接键入 `topic`。
4. 手动把 TASK 改成 `请用三句话解释 ${input.topic}。`，点击“保存新版本”。
5. 查看“变量”页，刷新页面后重新打开再看一次。

实际结果：

- 变量页现在会说明“在分段正文里写 `${input.}` 这样的占位符，或点分段标题旁的『插入变量』”，比第二轮完全没有语法说明明显进步。
- 点击“插入变量”会把 `${input.}` 写入 textarea，并把内部光标位置放在 `.` 与 `}` 之间；但焦点仍留在按钮，紧接着键入 `topic` 时正文没有变化。用户必须再点回文本框并自己定位光标。
- 手动写完整的 `${input.topic}` 并保存后，变量页会显示 `${input.topic} / 未登记 / 留空并记录`，刷新后仍在。
- 左侧同一提示词卡片依旧显示“5 段 · 0 变量”，变量页也没有“登记”“添加变量”或设置运行时来源、缺失策略的入口。

判断：发现占位符这半条链已经能用，但变量仍只能停在“未登记”，且插入动作没有把键盘焦点交给编辑框，所以是部分修复。

### 5. 🟡 提示词版本历史：仍存在

复现步骤：

1. 打开当时为 v2 的“Codex Round 2 提示词 1785222114277”。
2. 修改 TASK 并点击“保存新版本”，确认卡片和详情变为 v3。
3. 打开“版本”页，刷新页面后再次打开。
4. 另打开列表中的“版本历史验证”（v3）交叉检查。

实际结果：两个 v3 提示词的版本页都只显示当前版本及时间。亲自从 v2 保存到 v3 的提示词也看不到刚被替换的 v2，更没有内容对比或恢复入口。

判断：“保存新版本”的名称仍然承诺了用户实际无法查看的历史。

## 第二部分：自由使用——Agent 角色的创建、模型与版本维护

这一轮换到 Agent 角色管理，不再重复上一轮的提示词主流程。我实际完成了以下操作：

1. 打开“Agent 角色”；测试开始时列表有 138 条、每页 50 条。
2. 点击加号新建“Codex Round 3 角色 1785228046946”。
3. 填写角色“发布前检查员”、目标和“简洁、谨慎；不替用户执行发布或运行”的性格指令。
4. Runtime 选择“Codex（ACP）”，模型选择第二页来源的 `[基线] Codex · high`，点击“创建”。
5. 创建后只修改目标，点击“保存新版本”，再刷新并重新打开该角色。

顺畅的部分：

- 新建表单的“名称 / 角色 / 目标 / 性格与指令 / Runtime / 模型”顺序清楚；必填信息不足时“创建”保持禁用。
- 第二页的基线 Codex 在角色模型下拉里也能选择，说明“列出全部启用模型”的修复不仅覆盖主管 AI。
- 创建后名称、角色、目标、模型都正确进入详情；修改后的目标保存新版本并刷新后仍保留。
- “降级发生时会写入 RunEvent，不会静默替换模型”“Prompt 无法越权”等说明能建立正确的安全预期。

### 6. 🔴 Agent 权限、工具白名单和输出契约没有配置入口

复现步骤：

1. 进入“Agent 角色”，点击“新建角色”。
2. 填完名称、角色、目标、指令、Runtime 和模型并创建。
3. 在新角色详情向下查看“权限（引擎强制，Prompt 无法越权）”“工具与 MCP 白名单”“输出契约”。
4. 检查页面上的输入框、文本框、下拉框和按钮。

实际结果：新建表单明确提示“权限、工具白名单和输出契约建完再调”，但建完后权限只显示 `file none / 命令 none / 网络 none / 记忆 none / secret 无`，工具白名单为空，输出契约为“未声明”。详情中可操作的只有名称、目标、性格指令、模型、降级模型以及复制/删除/保存；上述三块没有开关、下拉、添加按钮或编辑动作。

影响：需要读文件、跑命令、访问记忆、调用 MCP 或要求结构化输出的 Agent 都无法从这个页面配置到可用状态。界面告诉用户“建完再调”，但没有下一步。

### 7. 🔴 保存 Agent 新版本会清空未改动的“性格与指令”

复现步骤：

1. 新建角色时在“性格与指令”填写“简洁、谨慎；不替用户执行发布或运行。”并创建。
2. 创建后的详情确认这段文字存在。
3. 只修改“目标”，不碰“性格与指令”。
4. 点击“保存新版本”，刷新页面并重新打开该角色。

实际结果：目标的新文本正确保留，但“性格与指令”变成空白。保存前页面里该字段仍有原文，保存后刷新才确认它已经丢失。

影响：这是静默数据丢失。用户只改一个字段并保存新版本，另一个未改字段会被清空；如果指令较长且没有外部副本，很难恢复。

### 8. 🟡 Agent 列表超过 100 条仍没有搜索或筛选

复现步骤：

1. 进入“Agent 角色”，观察列表总数和每页数量。
2. 检查页面所有输入控件和列表操作。
3. 尝试寻找一个不在当前页的旧角色。

实际结果：测试开始时共有 138 条、每页 50 条，只有“上一页 / 下一页”，页面没有搜索框、Runtime 筛选或名称筛选。新建项排在前面时容易找到；寻找旧角色只能逐页浏览。列表里还有多个同名“Codex 复测角色 … 副本”，纯浏览很难区分目标。

## 总体感受

第二轮最影响求助路径的三个问题——主管 AI 不懂应用、取消无回执、下拉漏掉第二页模型——这一轮都看到了实质改善。主管 AI 现在终于能给出可照着走的界面步骤，模型完整性也同时覆盖了 Agent 角色，修复是连贯的。

提示词变量处于“已经露出正确概念，但还没形成管理闭环”的阶段；版本页则仍名不副实。本轮新角度里，Agent 角色的基础创建和模型选择很顺，但权限配置缺口让很多角色无法真正获得工作能力，保存新版本清空未改字段更是需要优先处理的数据安全问题。
