## 修复不彻底 / 不一致（2 条）

### ❌ F1 · 代号守卫现在会误伤行尾注释

- 严重度：一般
- 位置：`apps/web/tests/no-internal-jargon.test.ts:47`

**实测**：在 `NotFoundPage.tsx` 写一行

```ts
import { Link } from 'react-router'; // 这处的历史见 M2 的说明
```

```
× 没有一处用户可见文本写着 M0–M9
  这些文案对用户露出了内部里程碑代号：…
```

**坏法**：去注释只剥「整行以 `//` 开头」的行（`/^\s*\/\/.*$/gmu`），
**行尾注释剥不掉**。而这条测试自己的文档注释写着「注释里提它是可以的」，
报错却说「这些文案对用户露出了内部里程碑代号」——**开发者会去找一个不存在的界面文案**。

上一轮 F3 已经指出过这一条（「去注释逻辑反了向」），这次只修了漏报那一半。

**修的方向**：把行尾注释也剥掉，例如先 `.replace(/\/\/[^\n]*$/gmu, '')`
再逐行扫（注意别误伤字符串里的 `//`，如 URL）。

### ❌ F2 · 记忆页复刻了概览页刚修掉的「分页藏太深」

- 严重度：**严重**（与原缺陷 5 同级）
- 位置：记忆页的 `.pager` 没有跟着加 `position: sticky`

六屏对照（60 条记忆时）：

| 屏       | position | 首屏可见 | 需要滚动    | 滚动容器         |
| -------- | -------- | -------- | ----------- | ---------------- |
| 概览     | `sticky` | ✅       | 0 px        | `.overview`      |
| **记忆** | `static` | ❌       | **2759 px** | `.memory__body`  |
| 执行记录 | static   | ✅       | 0 px        | （左栏独立滚动） |
| Agent    | static   | ✅       | 0 px        | 同上             |
| 提示词   | static   | ✅       | 0 px        | 同上             |
| 模型     | static   | ✅       | 0 px        | 同上             |

**这一轮新加的分页，掉进了同一个坑，而且比原来更深**
（2759 px vs 概览页原来的 2665 px）。

原因很清楚：概览页的修法是给它自己加 `sticky`，而不是给
「整页滚动的屏 + 分页」这个组合定一条规则。记忆页是这一轮才有分页的，
没人想起来它也属于那一类。

**修的方向**：分页控件默认吸底（在 `Pager` 组件层面做，而不是在每个用它的屏做），
这样下一个加分页的屏不会再掉进去。

## 建议级残留（1 条）

- 位置：`packages/contracts/tests/nodes.test.ts:16`

但现在 `seed` 已经进了 `NodeDefinition` 且有自己的守卫，
两张表的存在理由重叠了。**需产品确认**要不要合并。
