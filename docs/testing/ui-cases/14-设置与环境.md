### 权限策略

三张并排卡（`role="radiogroup"`）：

| 卡                  | 说明                                                       |
| ------------------- | ---------------------------------------------------------- |
| Review Every Change | 文件写入、命令与外部写操作逐项审批。适合陌生工作流。       |
| Workspace Safe      | 授权目录内可读写与执行已声明命令；Push、PR、删除仍需审批。 |
| Trusted Workflow    | 对指定已发布版本沿用保存策略；权限扩大后自动失效。         |

底部说明：「选「Review Every Change」时，脚本、worktree、commit、PR 与 MCP 工具节点
会在执行前挂起等你审批；批准过的节点恢复运行时不再重复询问。」

### 版本与更新

Web 形态：「当前 <版本> · Web 形态由服务端更新，刷新页面即为最新」
桌面形态：版本 Tag + 状态说明 + 「检查更新」/「下载更新」/「重启并安装」

## 用例

### SET-01 · 八档导航

- 类型：功能
- 操作：依次点八项
- 预期：
  1. 默认停在「运行环境与工具」
  2. 每项有 `role="tab"` + `aria-selected`
  3. 六档显示「这一档还没有可配置的项。」（**照实说而不是留一片空白**）
  4. 「安全与隐私」显示权限策略
- 失败判定：点了没反应；或空档显示白屏

### SET-02 · 环境检查自动跑

- 类型：功能
- 操作：进入这一屏
- 预期：
  1. 自动发起一次检查（不用点按钮）
  2. 汇总条显示结果
  3. 表格列出每一项
- 失败判定：要手动点才检查

### SET-03 · 表格五列都有内容

- 类型：功能 / 可解释性
- 操作：看表格
- 预期（每一行）：
  1. 能力：中文名
  2. 版本：真实版本号，没有时是「—」（不是空白也不是 `undefined`）
  3. **路径 / 来源**：真实路径。App 管理的前缀「App Managed · 」，
     系统的后缀「· 系统」
  4. 状态：图标 + 中文（就绪 / 需处理 / 可选 / 缺失）
  5. 非就绪且有详情时，状态下方显示详情
- 说明：「路径 / 来源」这一列**不是装饰**——用户要能自己确认应用用的是哪一个 git，
  装错版本的排查全靠它。
- 失败判定：路径列空着；或显示 `undefined`

### SET-04 · 「需要处理」只数必需项

- 类型：功能
- 前置：有一项状态是「可选」且缺失
- 预期：汇总条的「N 项」**不把可选项算进去**
  （可选项缺失不该让人以为环境坏了）
- 失败判定：可选项被计入待处理

### SET-05 · 重新检查

- 类型：功能
- 操作：
  1. 点「重新检查」
  2. 观察按钮
  3. 装上一个缺失的工具，再点一次
- 预期：
  1. 按钮变「检查中」并禁用
  2. 完成后结果刷新
  3. 装好之后那一行从「缺失」变「就绪」，版本与路径填上
- 失败判定：点了没有任何变化（不知道有没有真的重查）

### SET-06 · 复制安装命令

- 类型：功能
- 前置：至少一项缺失
- 操作：点那一行的「复制」
- 预期：
  1. 命令进了剪贴板（粘出来核对）
  2. 按钮有 `aria-label="复制 <能力> 的安装命令"`
  3. **复制后有反馈**（文字变化/提示），否则用户不知道成没成
- 失败判定：点了没反应也没反馈

### SET-07 · 命令的出处要写明

- 类型：安全 / 可解释性
- 操作：看缺失项的安装提示
- 预期：命令下方写「来自 <出处>」，让用户能自己判断要不要跑
- 失败判定：只给命令不给出处（用户在往终端里粘一条来路不明的命令）

### SET-08 · 应用不自己装东西

- 类型：安全（**产品原则**）
- 操作：找一找有没有「一键安装」按钮
- 预期：**没有**。只给可复制的命令 + 脚本提示
- 说明：替用户执行下载与解压，就要为「从哪下载、怎么校验签名、
  装坏了怎么回滚」全都做决定，而每个决定都是新的攻击面。
- 失败判定：出现了会自动下载安装的按钮

### SET-09 · 权限三档可选且落库

- 类型：功能
- 操作：
  1. 选「Workspace Safe」
  2. 刷新页面
  3. 去看侧栏底部
- 预期：
  1. 选中的卡有 `data-active="true"` + 填充的单选图标
  2. 刷新后仍是它（真的落库了）
  3. **侧栏底部同步显示**「Workspace Safe」+ 对应说明
- 失败判定：刷新后回到默认档（没落库）

### SET-10 · 三档的文案一字不差

- 类型：图纸符合性
- 操作：逐字比对三张卡的标题与说明
- 预期：与上表完全一致
- 失败判定：任何一个字不同

### SET-11 · 选档失败时退回原值

- 类型：边界
- 操作：断网 → 点另一档
- 预期：
  1. 显示错误（`role="alert"`）
  2. 选中态**退回原来那一档**
- 失败判定：留一个假的选中态——用户会以为已经改了
  （而引擎那边还是旧档，这是危险的不一致）

### SET-12 · 读不到设置时按最严的显示

- 类型：边界
- 操作：停掉 devserver，刷新，看权限策略
- 预期：显示 `Review Every Change`（最严的一档），**不报错**
- 说明：这与引擎的默认一致——读不到就按最严的办。
- 失败判定：显示最宽松的一档

### SET-13 · 权限档真的在拦

- 类型：安全（**核心承诺**）
- 操作：见 [B3 剧本 S6](personas/B3-安全与可解释性.md)
- 预期：Review Every Change 下脚本节点执行前挂起
- 失败判定：界面能选而引擎不拦

### SET-14 · 版本卡（Web 形态）

- 类型：功能
- 操作：看更新卡
- 预期：显示「当前 <版本> · Web 形态由服务端更新，刷新页面即为最新」
- 失败判定：Web 形态出现「检查更新」按钮（点了也没用）

### SET-15 · 版本卡（桌面形态）

- 类型：功能（**桌面必测**）
- 前置：`pnpm --filter @aiwf/desktop dev`
- 操作：
  1. 进设置页
  2. 看版本 Tag 与说明
  3. 点「检查更新」
- 预期：
  1. 版本号是**真实版本**（从 Tauri `getVersion()` 取），不是 `0.0.0`
  2. 开发构建显示「开发构建不检查更新（没有对应的发布版本）」
  3. 进页面时**自动检查一次**
  4. 检查中按钮 loading
  5. 有新版本时出现「下载更新」；下载完出现「重启并安装」
  6. 下载时有进度条
- 失败判定：版本显示 `0.0.0`（说明走了 `import.meta.env` 而不是
  `useAppVersion()`，应用会把自己当 dev 版而跳过更新检查）

### SET-16 · 版本读不到时说清原因

- 类型：边界
- 操作：制造版本读取失败（桌面形态下权限缺失时会这样）
- 预期：
  1. 显示 Tag「未知」
  2. 显示错误原因
  3. 说明「版本未知时不会检查更新，避免拿错版本号做比较。」
- 失败判定：显示「尚未检查更新」（那是另一种含义）

### SET-17 · 不主动弹更新提示

- 类型：体验（**产品决策**）
- 操作：在别的屏停留，观察有没有更新弹窗
- 预期：**没有**。只有进到设置页才提示
- 说明：这是一个会长时间挂着运行的工具，打断正在等审批的用户
  比晚一天更新代价更大。
- 失败判定：全局弹更新提示

### SET-18 · 空档的文案

- 类型：体验
- 操作：点「通用」「通知」「高级」等
- 预期：「这一档还没有可配置的项。」
- 判定：这是有意的（图纸只画了 env 那一档）。
  但**六档里全是这句话**，用户会觉得这个设置页是个壳子——
  记进建议：要不要在导航上标出哪些档已经有内容。

### SET-19 · 三问清点

- 类型：体验
- 操作：对这些做三问：
  表格里的**路径**（想复制它、想在访达里打开）、
  版本号（想复制）、**状态图标**（想点它看详情）、
  汇总条的「N 项待处理」（想点它跳到那几行）、
  脚本提示里的 `bash scripts/install-deps.sh`（想复制）
- 重点：
  1. **路径能复制吗**？排查装错版本时用户要拿它去终端里核对
  2. **`bash scripts/install-deps.sh` 这条命令能复制吗**？
     旁边的缺失项都有复制按钮，这一条有吗
