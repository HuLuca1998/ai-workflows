# 01 · 应用外壳与导航

外壳是每一屏都带着的东西：标题栏、主导航、路由、全局快捷键、
以及两个可能在任何位置弹出来的浮层（主管 AI 抽屉、MCP 确认卡）。

外壳坏了，后面十六个模块的测试都不可信——所以它排第一。

## 元素清单

先照着这张表把界面上的东西认全。**「能点吗」一列是你要去验证的**，
不是抄答案：写着「应可点」的点不动就是缺陷，写着「纯展示」的能点也要记录。

### 标题栏（高 44px，`<header class="title-bar">`）

| #   | 元素                 | 长什么样                                   | 能点吗     | 点了应该怎样             |

| 5   | 斜杠分隔             | `/`                                        | 纯展示     | —                        |

## 用例

### SHELL-01 · 首次打开，外壳三处提示都在「尚未配置」态

- 类型：功能 / 体验
- 前置：**全新数据库**（`rm -rf /tmp/aiwf-ui-test` 后重起 devserver），刷新页面
- 操作：
  1. 打开 `http://localhost:5173`
  2. 截图，观察标题栏与侧栏底部
- 预期：
  1. 标题栏面包屑显示「尚未授权工作目录」，后面是「/」与「概览与工作流」
  2. 侧栏底部第一块显示「未设置权限档」，副文本「首次配置时授权工作目录并选择权限档」
  3. 侧栏底部第二块显示「环境尚未检查」，图标是警告圈（`ph-warning-circle`）而不是心跳
  4. 三处的文字**一字不差**
- 失败判定：显示了一个假的正常状态（如「环境正常」但从没检查过）

### SHELL-02 · 九个导航项齐全且顺序正确

- 类型：功能
- 操作：逐个数侧栏的导航项
- 预期：
  1. 恰好 9 项，顺序为：概览与工作流 → 工作流编辑器 → 执行记录 → 记忆 →
     Agent 角色 → 提示词库 → 模型 → 设置与环境 → 首次配置
  2. 每项左侧有图标，图标与元素清单表里的一致
  3. 上方有「工作区」分组标题
- 失败判定：顺序不同、缺项、图标错位

### SHELL-03 · 每个导航项都能到达对应屏，且面包屑跟着变

- 类型：功能
- 操作：依次点击 9 个导航项，每次截图
- 预期（每一项都要满足）：
  1. URL 变成对应路径
  2. 该项出现选中态（当前项与其他项在视觉上可区分）
  3. **标题栏面包屑的最后一段变成该项的名字**
  4. 主内容区渲染出对应的屏，不是空白
- 失败判定：面包屑不跟着变；点了 URL 变但内容没变；某一项白屏

### SHELL-04 · 「工作流编辑器」不带 id 时给的是引导而不是空画布

- 类型：功能 / 体验
- 操作：点侧栏「工作流编辑器」
- 预期：
  1. 显示标题「工作流编辑器」与副文本「设计与维护流程」
  2. 正文是「先在**概览与工作流**里选一个工作流，或新建一个。」
  3. 其中「概览与工作流」是**可点的链接**，点了去 `/`
- 失败判定：显示了一个没有工作流的空画布（用户会在上面白干）

### SHELL-05 · ⌘K 开关主管 AI 抽屉

- 类型：功能 / 无障碍
- 操作：
  1. 在概览页点一下空白处（确保焦点不在输入框）
  2. 按 ⌘K（Windows/Linux：Ctrl+K）
  3. 再按一次 ⌘K
  4. 再按 ⌘K 打开，然后按 Esc
- 预期：
  1. 第一次：抽屉从右侧滑入，宽 468px，标题「主管 AI」
  2. 第二次：抽屉关闭
  3. Esc：抽屉关闭
  4. 抽屉打开时，主内容区仍可见（不是全屏遮盖）
- 失败判定：⌘K 无效；开了关不掉；Esc 不生效

### SHELL-06 · 在输入框里按 ⌘K 仍然是呼出抽屉（不是选中文本）

- 类型：边界
- 操作：
  1. 点进概览页搜索框，输入几个字
  2. 按 ⌘K
- 预期：抽屉打开（这是全局快捷键，代码里没有排除输入框）
- 说明：**记录实际行为**。若与预期不同，说明快捷键在输入框里被让开了，
  那也是合理设计——写清楚实际是哪种。

### SHELL-07 · 点标题栏「询问 AI」按钮等价于 ⌘K

- 类型：功能
- 操作：点击标题栏右侧的「询问 AI ⌘K」按钮两次
- 预期：第一次打开抽屉，第二次关闭
- 失败判定：只能开不能关；按钮上的 `⌘K` 与实际快捷键不一致

### SHELL-08 · 窗口窄于 1360px 时侧栏收成图标栏

- 类型：功能 / 体验 / 边界
- 操作：
  1. 窗口宽度调到 1400px → 截图
  2. 调到 1360px → 截图
  3. 调到 1359px → 截图
  4. 调到 1280px（最小支持尺寸）→ 截图
- 预期：
  1. 1400 与 1360：侧栏展开，显示文字与「工作区」标题、权限档块
  2. 1359 与 1280：侧栏收成窄条（`data-collapsed="true"`），
     只剩图标，「工作区」标题与权限档块隐藏
  3. 收起后**鼠标悬停图标有 title 提示**该项名字
  4. 收起后环境状态行只剩图标
  5. 任何宽度下都**不出现横向滚动条**
- 失败判定：阈值不是 1360；收起后读屏拿不到项名（应保留 `sr-only` 文本）

### SHELL-09 · 收起状态下导航仍可用且可读

- 类型：无障碍
- 前置：窗口 1280px
- 操作：
  1. 用无障碍树查看侧栏
  2. 点击其中三个图标
- 预期：
  1. 每个链接仍有可访问名（「执行记录」等），不是空的
  2. 点击行为与展开时一致
- 失败判定：可访问名丢失，读屏只念「链接」

### SHELL-10 · 浏览器前进后退

- 类型：功能 / 边界
- 操作：
  1. 依次访问 `/` → `/runs` → `/models` → `/settings`
  2. 后退 3 次
  3. 前进 3 次
- 预期：
  1. 每次都回到/去到正确的屏，面包屑同步
  2. 不出现白屏、不重复发起大量请求
  3. 侧栏选中态跟着变
- 失败判定：后退后面包屑还停在上一屏

### SHELL-11 · 不存在的路径给 NotFound

- 类型：边界
- 操作：地址栏输入 `http://localhost:5173/不存在的路径`
- 预期：
  1. 显示 NotFound 页，不白屏
  2. 侧栏与标题栏仍在（外壳不受影响）
  3. 面包屑显示「未知位置」
- 失败判定：整页白屏或崩溃

### SHELL-12 · 授权工作目录后，三处提示同时更新

- 类型：功能 / 可解释性
- 前置：全新库
- 操作：
  1. 去「首次配置」
  2. 点底部主按钮完成授权（缺项时先点一次展开命令，再点「装好了，继续」）
  3. 被跳转回概览页后，观察标题栏与侧栏
- 预期：
  1. 标题栏面包屑显示 `~/Library/Application Support/AI Workflows`
  2. 侧栏权限档块显示「Review Every Change」+
     「文件写入、命令与外部写操作逐项审批。」
  3. 侧栏环境行显示「环境正常 · 上次检查 <时间>」，图标变成心跳
  4. 刷新页面后三处仍然如此（说明真的落库了）
- 失败判定：点了按钮跳转了，但三处提示没变——
  这是「按钮承诺了、状态没落地」，严重级

### SHELL-13 · 权限档改了之后侧栏跟着变

- 类型：可解释性
- 操作：
  1. 去设置 → 运行环境与工具 → 权限策略
  2. 选「Workspace Safe」
  3. 回到概览页看侧栏
- 预期：侧栏显示「Workspace Safe」+
  「授权目录内可读写与执行已声明命令；Push、PR、删除仍需审批。」
- 失败判定：侧栏还是旧档位（需要刷新才更新的话，记为一般缺陷）

### SHELL-14 · MCP 确认卡在任何一屏都会弹

- 类型：功能 / 安全
- 操作：
  1. 停在「记忆」屏
  2. 用 curl 造一次待确认（见 [B3 剧本 S7](personas/B3-安全与可解释性.md)）
  3. 等待最多 2 秒
  4. 切到「模型」屏，再造一次
- 预期：
  1. 两次都弹出确认卡，且**不遮挡到无法操作**当前屏
  2. 卡片有标题「MCP 客户端要写入：<工具名>」
  3. 入参以格式化 JSON 展示
  4. 有「拒绝」与「批准这次写入」两个按钮
- 失败判定：只在某些屏出现；把整屏挡死

### SHELL-15 · 桌面形态：窗口可拖动、交通灯不重叠

- 类型：功能（**桌面必测**）
- 前置：`pnpm --filter @aiwf/desktop dev`
- 操作：
  1. 按住标题栏空白处拖动窗口
  2. 按住面包屑文字拖动
  3. 观察左上角
- 预期：
  1. 两处都能拖动窗口
  2. 左上角只有一组 macOS 交通灯（不是两组重叠）
  3. 交通灯与面包屑之间有安全间距，不重叠
- 失败判定：拖不动（多半是 capabilities 缺 `core:window:allow-start-dragging`）；
  出现两组圆点

### SHELL-16 · 外壳的三问清点

- 类型：体验
- 操作：按[总纲 §3.6](README.md) 对元素清单表里标「待验证」的三项做三问：
  工作目录路径（#4）、权限档块（#20）、环境状态行（#21）
- 预期：填出清点表，给出判定
- 说明：这三处都是**看起来该点、也很想点**的元素
  （用户看到「尚未授权工作目录」的第一反应就是点它）。
  点不动的话记「想点但点不动」，并评估严重度：
  它是否有其他明显入口能到达同样的地方（有 → 一般；没有 → 严重）。
