# 10 · 记忆管理

路由 `/memory`。图纸「04 记忆管理」。

这一屏的特别之处：**记忆会注入后续每一次 AI 调用**，
所以它既是长期上下文，也是一条持续生效的指令。三条设计由此而来：

1. AI 提议要**确认才生效**（模型自己给自己加指令是不行的）
2. **停用是比删除更轻的一档**（先停掉看看有没有影响）
3. **密钥禁止写入**

数据行的四列：

- Key 列：key + 作用域标签 +（停用时）「已停用」+（过期时）「已过期」

- 更新列：更新时间 + 标签
- 操作列：停用 / 删除两个图标按钮

## 前置：怎么造数据

从界面建不出记忆（没有「新建」按钮）——这本身值得记录（见 MEM-14）。
用 API 铺：

```bash
curl -s -XPOST http://127.0.0.1:5177/ipc/memory_create \
  -H 'content-type: application/json' \
  -d '{"scope":"global","key":"团队用 pnpm","value":"这个仓库统一用 pnpm，不要用 npm","createdBy":"luca"}'

# AI 提议的（未启用）
curl -s -XPOST http://127.0.0.1:5177/ipc/memory_create \
  -H 'content-type: application/json' \
  -d '{"scope":"workflow","key":"测试端口","value":"devserver 默认跑在 5177","source":"ai_proposed","enabled":false,"createdBy":"主管 AI"}'
```

各作用域至少造一条，方便测 chips。

## 用例

### MEM-01 · 空态

- 类型：功能
- 前置：一条记忆都没有
- 预期：
  1. 显示空态那句话（一字不差）
  2. 「N 条」显示 0
  3. 表头仍在
  4. 底部说明常驻
- 失败判定：整片空白

### MEM-02 · 六个作用域 chip

- 类型：功能
- 前置：每个作用域各有一条记忆
- 操作：依次点 全部 / 全局 / 工作区 / 工作流 / Agent / 会话
- 预期：
  1. 每次都只显示该作用域的条目
  2. 选中的 chip 有 `data-active="true"`
  3. 「N 条」跟着变
  4. 筛选发给**后端**（不是前端过滤）
- 失败判定：条数不跟着变

### MEM-03 · 搜索

- 类型：功能 / 体验
- 操作：
  1. 输入一个 key 的一部分，**不按回车**，等 1 秒
  2. 按回车
- 预期：
  1. **记录实际行为**：当前实现是「只有回车才搜」
  2. 与概览页、执行记录、Agent 页的「输入即搜」**不一致**
- 判定：不一致 → 记为体验缺陷（用户在别处学会了打字就搜，
  到这里打字没反应会以为搜索坏了）。详见
  [F3 剧本 R2](personas/F3-前端代码审查.md) 的搜索交互对照表。

### MEM-04 · 搜索能搜内容与标签

- 类型：功能
- 操作：搜一个只出现在 value 里的词；再搜一个只在标签里的词
- 预期：都能搜到（占位文字承诺了「搜索 key、内容或标签」）
- 失败判定：只能搜 key——**界面上承诺了却不存在**

### MEM-05 · AI 提议区单独一块

- 类型：功能 / 安全
- 前置：有一条 `source=ai_proposed` 且 `enabled=false` 的记忆
- 预期：
  1. 它出现在**上方的提议区**，不在下方表格里
  2. 提议区标题「AI 提议写入」+ 说明「确认后才保存，并注入后续调用」
  3. 条目显示 key、作用域标签、内容、「来源 <谁>」
  4. 有「忽略」与「采纳并保存」两个按钮
  5. **在采纳之前，它不会被注入任何 AI 调用**（去 MEM-13 验证）
- 失败判定：AI 提议的条目直接混在表格里生效了
  （那模型就能自己给自己加指令，**严重**）

### MEM-06 · 采纳提议

- 类型：功能
- 操作：点「采纳并保存」
- 预期：
  1. 该条从提议区消失
  2. 出现在下方表格里，状态是启用
  3. 「N 条」不变（它本来就算在内）
- 失败判定：采纳后消失了（数据丢了）

### MEM-07 · 忽略提议

- 类型：功能
- 操作：点「忽略」
- 预期：
  1. 该条**被删除**（不是停用）
  2. 提议区里没有它了
  3. 表格里也没有
- 说明：确认「忽略」的语义是删除还是停用——两者对用户的含义不同，
  界面上分得清吗？分不清记进建议。

### MEM-08 · 停用与启用

- 类型：功能
- 操作：
  1. 点某条的电源图标
  2. 再点一次
- 预期：
  1. 停用后：该行出现「已停用」标记，行有 `data-enabled="false"`
  2. **仍留在列表里**（停用是比删除更轻的一档，用户要知道它为什么不生效）
  3. 按钮的 `aria-label` 在「停用 <key>」与「启用 <key>」之间切换
  4. 再点恢复启用
- 失败判定：停用后条目消失了

### MEM-09 · 删除

- 类型：功能 / 边界
- 操作：点垃圾桶图标
- 预期：
  1. **记录实际行为**：有没有二次确认？
  2. 删除后该行消失，「N 条」-1
- 判定：**没有二次确认的话，记为缺陷**——
  这一屏的删除是不可逆的（记忆没有回收站），而其他屏
  （Agent、提示词、模型）的删除都有「确认删除」这一步。
  同一个应用里两种删除行为不一致。

### MEM-10 · 过期的记忆

- 类型：边界
- 前置：造一条 `expiresAt` 是过去时间的记忆
- 预期：该行显示「已过期」标记，且仍在列表里
- 失败判定：过期的直接不显示了（用户不知道它为什么不生效）

### MEM-11 · 长内容与特殊字符

- 类型：边界
- 前置：造几条极端的：
  - value 是 5000 字的长文
  - value 含换行与代码块
  - key 是 emoji
  - value 是 `<script>alert(1)</script>`
- 预期：
  1. 长文不撑破表格布局（截断或换行，截断要有 title）
  2. 脚本原样显示为文本，**不弹窗**
  3. 表格列宽保持稳定
- 失败判定：一条长记忆把整张表挤变形

### MEM-12 · 密钥禁止写入

- 类型：安全
- 操作：见 [B3 剧本 S9](personas/B3-安全与可解释性.md)
- 预期：value 是 `sk-TESTLEAK-…` 的记忆**被拒绝**
- 失败判定：写进去了（它会被注入每一次 AI 调用，**严重**）

### MEM-13 · 记忆真的被注入了，且可溯源

- 类型：可解释性（**M4 出口标准**）
- 操作：
  1. 确保有一条启用的记忆
  2. 跑一条含 AI 节点的工作流（**用 `acp.codex`**）
  3. 去执行记录看事件流
- 预期：
  1. 运行开始时有一条 `system.memory_injected` 事件
  2. 它记录了这次运行带着哪些记忆
  3. 事件在**运行开始时**就写了（不是等某个 AI 节点跑完——
     那个节点可能失败、可能被取消）
- 失败判定：找不到这条事件（那么「记忆注入可溯源」就是空话）

### MEM-14 · 界面上能不能新建记忆

- 类型：体验
- 操作：找「新建记忆」的入口
- 预期：**记录实际情况**——当前这一屏没有新建按钮
- 判定：
  - 如果产品设计就是「只由 AI 提议 + 用户确认」，那么空态那句话
    （「AI 在运行结束时会提议…你确认后才会写进来」）已经说清了 → 不是缺陷
  - 但用户想主动记一条事实时怎么办？记进**建议**
- 说明：图纸「04 记忆管理」里有没有新建入口？去核对
  （这条同时是 [F1 剧本第二副眼镜](personas/F1-界面与体验.md) 的活）

### MEM-15 · 分页缺失

- 类型：边界 / 一致性
- 操作：造 200 条记忆，看这一屏
- 预期：**记录实际情况**——当前这一屏**没有分页控件**，
  而其他五个列表页都有
- 判定：
  1. 200 条一次铺完，页面有多长？滚动流畅吗？
  2. `memory_list` 请求带 limit 吗？
  3. 与其他屏不一致 → 缺陷（详见 [F3 剧本 R2](personas/F3-前端代码审查.md)）

### MEM-16 · 后端挂掉

- 类型：边界
- 操作：停掉 devserver，刷新
- 预期：显示错误（`role="alert"`），**不显示**「还没有记忆」那套空态
- 失败判定：显示空态，用户以为记忆都没了

### MEM-17 · 三问清点

- 类型：体验
- 操作：对这些做三问：
  提议条目本身（#8，想点它看完整内容与来龙去脉）、
  表头（#11，想按更新时间排序）、数据行（#12，想点开看详情/编辑）、
  作用域标签（想点它筛选）、标签（想点它筛选）、
  「来源」（想知道是哪次运行提议的）
- 重点：
  1. **数据行能编辑吗**？记忆写错了怎么改？（只能删了重来？）
  2. **「来源」能追溯吗**？某条记忆是哪次运行提议的，点得过去吗？
  3. **作用域标签能点吗**？看到一条「工作流」作用域的记忆，
     用户会想知道是哪条工作流
