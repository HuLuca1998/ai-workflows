# 15 · 首次配置

路由 `/onboarding`。图纸「06 首次安装与检测」。

这一屏的产品原则写在页面第二段：**我们不会静默修改系统**。
缺什么给一行可复制的命令，由用户自己执行——不使用 sudo，
不改动 shell profile，也不把 App 工具写入全局 PATH。

## 用例

### ONB-01 · 进来自动检测

- 类型：功能
- 操作：打开 `/onboarding`
- 预期：
  1. 自动跑一次环境检测（不用点按钮）
  2. 「工具与运行时」块列出检测结果
  3. 「ACP Runtime 检测」块单独列 ACP 相关项
- 失败判定：要点按钮才检测

### ONB-02 · 四个步骤条

- 类型：功能 / 体验
- 操作：看顶部步骤条
- 预期：
  1. 四步文字与上表一致
  2. 已完成的步骤有标记（`data-done`）
  3. **用户能看出自己在第几步**
- 判定：当前实现只有第 1 步和「第 2 步且没有缺失项」时才标完成，
  第 3、4 步永远不亮。**这算不算「界面上承诺了却不存在」**？
  记录实际行为并判定。
- 补充：步骤条能点吗（用户会想点第 3 步跳过去）

### ONB-03 · 检测行的四列

- 类型：功能 / 可解释性
- 操作：看每一行
- 预期：
  1. 名称（中文）
  2. 版本（没有时是「—」）
  3. 路径（没装时显示 detail 或「未安装」）
  4. 状态：就绪 / 需处理 / 可选 / 缺失
  5. 缺失项额外显示命令 + 「来自 <出处>」
  6. 行上有 `data-capability` 与 `data-status`
- 失败判定：出现 `undefined`

### ONB-04 · ACP 块单独一段

- 类型：功能
- 操作：看「ACP Runtime 检测」块
- 预期：
  1. 只列 `acp.` 开头的能力
  2. 说明：「AI 节点与主管 AI 靠它；没有它其余功能照常」
  3. **codex 排在前面**（契约的 `AGENT_RUNTIMES` 把 `acp.codex` 排第一，
     探测顺序、默认值都跟着它——见 CLAUDE.md）
- 失败判定：claude 排在前面

### ONB-05 · 主按钮的三种文案

- 类型：功能（**这条要分三种状态测**）

| 状态                    | 按钮文案               | 点了应该怎样               |
| ----------------------- | ---------------------- | -------------------------- |
| 有缺失项 + 还没展开命令 | 「确认并安装（N 项）」 | **展开命令清单**（不安装） |
| 有缺失项 + 已展开命令   | 「装好了，继续」       | 授权并跳转                 |
| 没有缺失项              | 「授权工作目录并开始」 | 授权并跳转                 |

- 预期：三种状态下文案与行为都对
- 说明：「确认并安装」这一档**按已确认的偏离改成只检测、给可复制的命令**——
  应用自己不下载任何东西。
- 失败判定：点「确认并安装」真的开始下载安装

### ONB-06 · 命令清单

- 类型：功能 / 安全
- 前置：至少一项缺失
- 操作：点「确认并安装（N 项）」
- 预期：
  1. 下方出现「要执行的命令」块
  2. 说明解释为什么不替你装（「每个决定都是新的攻击面」）
  3. 每条命令带名称与出处
  4. 说明里写明「这些命令不使用 sudo，也不改你的 shell profile」
  5. 另给一键脚本 `bash scripts/install-deps.sh`，
     并说明它「会先打印每条要执行的命令，确认后才执行；`--dry-run` 只看不装」
- 失败判定：命令没有出处；或清单里的条数与「N 项」对不上

### ONB-07 · 命令能不能复制

- 类型：体验
- 操作：找复制按钮
- 预期：**记录实际情况**
- 判定：设置页的环境健康表**每条命令都有「复制」按钮**，
  这一屏的命令清单有吗？没有 → 一致性缺口，
  而且用户要手选一长串命令（容易选漏选多）→ 记为缺陷

### ONB-08 · 「仅检测，不安装」

- 类型：功能
- 操作：点它
- 预期：重新检测，不做任何别的事
- 失败判定：与主按钮行为相同（那这个按钮就没有存在意义）

### ONB-09 · 授权工作目录真的落库（**关键**）

- 类型：功能 / 可解释性
- 前置：全新库
- 操作：点主按钮走完授权
- 预期：
  1. 跳转到 `/`
  2. **标题栏面包屑**显示 `~/Library/Application Support/AI Workflows`
  3. **侧栏权限档块**显示「Review Every Change」+ 对应说明
  4. **侧栏环境行**显示「环境正常 · 上次检查 <时间>」
  5. **刷新页面后三处仍然如此**
- 失败判定：跳转了但三处提示没变——
  这是「按钮承诺了、状态没落地」，**严重级**
  （codex 复测的原话：「按钮承诺『用默认目录开始』，实际状态没有落地」）

### ONB-10 · 默认给最保守的权限档

- 类型：安全
- 操作：授权后去设置页看权限策略
- 预期：`Review Every Change`（最严的一档）
- 说明：用户还没表达过对任何工作流的信任程度，默认放宽等于替他做了
  一个他不知道自己做过的决定。
- 失败判定：默认给了 Workspace Safe 或 Trusted Workflow

### ONB-11 · 授权失败时留在这一屏

- 类型：边界
- 操作：断网 → 点主按钮
- 预期：
  1. **不跳转**
  2. 显示错误（`role="alert"`）
- 说明：跳走的话用户看到的还是「尚未授权」，而他刚刚明明点过按钮——
  那种不一致会让人怀疑整个应用。
- 失败判定：跳转了但状态没落地

### ONB-12 · 「将写入的位置」

- 类型：可解释性 / 安全
- 操作：看那一块
- 预期：
  1. 显示 `~/Library/Application Support/AI Workflows/{workflows,runs,artifacts,logs}/`
  2. 下一行：`# Secret 只保存在 Keychain，不写入以上目录`
- 失败判定：路径与实际写入位置不符（去磁盘上核对）

### ONB-13 · 导出脱敏诊断报告

- 类型：功能 / 安全
- 操作：点「导出脱敏诊断报告」
- 预期：
  1. 显示「诊断报告已导出到 <路径>」（`role="status"`）
  2. 文件真的存在
  3. **不含明文 Secret**（见 [B3 剧本 S5](personas/B3-安全与可解释性.md)）
- 说明：这一屏没有 runId，所以它走的是 `env.diagnostics` 而不是
  `run.diagnostics`——但**过的是同一个脱敏器**。去验证这一点。
- 失败判定：导出的报告里有密钥

### ONB-14 · 配置过之后还会不会拦人

- 类型：边界
- 操作：
  1. 完成授权
  2. 再次点侧栏「首次配置」
- 预期：能正常进入（不是被跳走），且能重新检测
- 说明：配置过的记号存在 localStorage（`aiwf.onboarding.skipped`）。
  隐私模式下 localStorage 会抛异常——**那时也不该挡住用户往下走**。
- 失败判定：隐私模式下点按钮报错

### ONB-15 · 全新设备 10 分钟内跑完内置示例

- 类型：功能（**M5 出口标准**）
- 操作：从全新库开始计时：
  1. 打开应用 → 首次配置 → 授权
  2. 建一条工作流（用模板）
  3. 跑起来直到成功
- 预期：**10 分钟内**完成，全程不需要看文档
- 记录：每一步花了多久、卡在哪
- 失败判定：超过 10 分钟，或中途卡死需要外部知识

### ONB-16 · 三问清点

- 类型：体验
- 操作：对这些做三问：
  步骤条的四步（#1，想点它跳步）、
  检测行的**路径**（想复制）、
  检测行的**状态**（想点它看为什么是这个状态）、
  「将写入的位置」里的路径（想点它打开目录）、
  诊断报告路径（#14，想点它打开）
- 重点：
  1. **诊断报告导出后，用户怎么拿到它**？路径能点开吗、能复制吗
  2. **缺失项的行**——用户看到「缺失」的下一个动作是「怎么装」，
     命令就在同一行，那够不够近？还是要滚到底部的命令清单里去找
