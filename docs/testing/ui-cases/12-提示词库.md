# 12 · 提示词库

路由 `/prompts`。图纸「06 提示词库」：266px 左栏 + 详情四个 tab。

四条产品规则在这一屏兑现：

1. **系统调用 AI 的每一处都在这里**——内置条目不能删
   （删掉就意味着某处调用没有提示词可用，而那处调用不会因此消失）
2. **框架分段可见可改**——分段是有序数组，不是一整块文本
3. **Secret 只以引用形式出现**——预览也不展开
4. **运行记录引用具体版本**——保存是「保存新版本」，版本号只增不改

## 元素清单

### 左栏（266px，可拖动）

| #   | 元素     | 内容                                                                        | 能点吗   |
| --- | -------- | --------------------------------------------------------------------------- | -------- |
| 1   | 小标题   | 「提示词库」                                                                | 纯展示   |
| 2   | 新建     | `+`，`aria-label="新建提示词"`                                              | 应可点   |
| 3   | 搜索框   | 占位「搜索名称、变量或正文」                                                | 应可输入 |
| 4   | 分组标题 | 组名 + 该组条数                                                             | 纯展示   |
| 5   | 条目     | 名称 + 「N 段 · N 变量」+ 「内置」/「vN」                                   | 应可点   |
| 6   | 分页     | 50 条一页                                                                   | 应可点   |
| 7   | 底部说明 | 「系统调用 AI 的每一处都在这里：节点、⌘K 协作、记忆提议、通知与失败归因。」 | 纯展示   |
| 8   | 空态     | 「还没有提示词。系统调用 AI 的每一处都会在这里留下一条，可见也可改。」      | 纯展示   |

### 详情区头部

名称 + 「<分组> · vN」+ 「复制」+「删除」（内置没有）+「保存新版本」。
内置条目额外显示：「内置提示词不能删除 —— 删掉就意味着某处 AI 调用没有提示词可用。要改的话先复制一份。」

### 四个 tab

`模板` · `变量` · `预览` · `版本`，右侧常驻小字
「框架分段可见可改 · 保存后新运行生效」。

## 用例

### PMT-01 · 列表按分组聚合

- 类型：功能
- 预期：
  1. 条目按分组聚合，每组一个标题 + 条数
  2. 每条显示「N 段 · N 变量」与版本
  3. 内置条目标「内置」
- 失败判定：分组计数与组内条数对不上

### PMT-02 · 搜索

- 类型：功能 / 体验
- 操作：输入名称的一部分，**不按回车**，等 1 秒；再按回车
- 预期：**记录实际行为**——当前实现是「只有回车才搜」
- 判定：与概览页 / 执行记录 / Agent 页的「输入即搜」不一致 → 体验缺陷
  （详见 [F3 剧本 R2](personas/F3-前端代码审查.md)）
- 补充：占位说能搜「名称、变量或正文」——**三样都试一遍**，
  搜不到的记为「界面上承诺了却不存在」

### PMT-03 · 新建提示词

- 类型：功能
- 操作：
  1. 点 `+`
  2. 分组输入框：看有没有已有分组的建议（datalist）
  3. 填分组与名称 → 点「创建」
- 预期：
  1. 表单可访问名「新建提示词」
  2. 分组是**自由文本 + 已有分组建议**（逼用户从枚举里选的话新场景没地方放）
  3. 说明：「会按框架分段建出骨架：Role / Task / Context / Constraints / Output contract。」
  4. 创建后自动选中它，停在「模板」tab
  5. 模板 tab 里有**五个空分段**，标题就是那五个
- 失败判定：建出来是一片空白（让用户对着空白想「该写哪几段」是最没必要的坎）

### PMT-04 · 模板 tab · 编辑分段

- 类型：功能
- 操作：选一个**非内置**提示词 → 模板 tab → 改某一段的正文
- 预期：
  1. 每段是一个 textarea，标签是段标题
  2. textarea 的行数**随内容增长**（至少 3 行）
  3. 只改这一段，**其余段不受影响**
  4. 改完后没保存时切到别的 tab 再切回来，改动还在
- 失败判定：改一段把别的段清空了

### PMT-05 · 内置的只读

- 类型：功能 / 安全
- 操作：选一个内置提示词 → 模板 tab
- 预期：
  1. 分段是 `<pre>` 只读展示，**不是输入框**
  2. 每段标题旁**没有**「插入变量」按钮
  3. 底部**没有**「添加分段」
  4. 点「保存新版本」时报错：
     「内置提示词不能直接改 —— 先「复制」一份，副本是可编辑的。」
- 失败判定：内置的能直接改（改它等于改掉系统某处调用的行为，而别人也在用）

### PMT-06 · 插入变量

- 类型：功能
- 操作：非内置提示词 → 某段标题旁点「插入变量」
- 预期：
  1. 正文里插入 `${input.}`
  2. **焦点回到正文**，光标停在 `${input.` 与 `}` 之间，
     接着打字就能补完变量名
  3. 切到「变量」tab，这个占位符出现在表里
- 失败判定：插入后焦点丢了，用户要自己点回去再挪光标

### PMT-07 · 添加分段

- 类型：功能 / 边界
- 操作：
  1. 点底部「添加分段（Examples / 失败处理 / 语言风格…）」
  2. 输入「Examples」→ 点「添加」
  3. 再添加一个**同名**的「Examples」
  4. 添加一个空标题
- 预期：
  1. 出现输入框（`aria-label="新分段的标题"`，占位「Examples」）
  2. 添加成功，新段出现在最后
  3. **同名被拒**（会让 key 撞车，也会让「Role」出现两次）
  4. 空标题被拒
  5. 有「取消」可以退出
- 失败判定：能添加同名段

### PMT-08 · 保存新版本

- 类型：功能
- 操作：改分段 → 点「保存新版本」
- 预期：
  1. 保存成功
  2. 版本号 +1（头部与左栏条目都变）
  3. 「版本」tab 里多一条历史
- 失败判定：版本号不变

### PMT-09 · 没有改动时保存

- 类型：边界
- 操作：不改直接点「保存新版本」
- 预期：显示「没有改动可保存。」
- 失败判定：产生一个内容相同的新版本

### PMT-10 · 改了没保存就切走

- 类型：边界（**数据丢失风险**）
- 操作：
  1. 改某段正文（不保存）
  2. 点左栏另一条提示词
  3. 再切回来
- 预期：**记录实际行为**——当前实现切换时会 `setSections(null)`，
  也就是**改动直接丢弃，且没有提醒**
- 判定：没有任何提醒 → 缺陷（用户会丢掉刚写的一段提示词）。
  与编辑器的 beforeunload 拦截对比：那边拦了，这边没拦，
  同一个应用里两种行为。

### PMT-11 · 变量 tab

- 类型：功能
- 操作：切到「变量」tab
- 预期：
  1. 表头三列：变量 / 运行时来源 / 缺失时
  2. **变量以编辑中的正文为准**——刚在正文里写的 `${input.repo}`
     立刻出现在表里（不是只显示后端存的那份）
  3. 正文里有的排前面，存过但正文里没有的跟在后面并标「正文里没用到」
  4. 「缺失时」显示中文：留空并记录 / 直接失败 / 用默认值
  5. 没有变量时显示提示，教用户写 `${input.}` 或点「插入变量」
  6. 底部：「Secret 只能以引用形式出现，预览与日志中永不展开明文。」
  7. **这张表没有「添加」按钮**是有意的——变量是写在正文里的占位符
- 失败判定：正文里写了变量但表里不显示（「0 变量」与正文对不上）

### PMT-12 · 变量识别的边界

- 类型：边界
- 操作：在正文里写这些，看变量表：
  - `${input.repo}` —— 正常
  - `${input.repo}` 写两遍 —— 应只算一次
  - `${ input.repo }`（带空格）
  - `${}`（空）
  - `$input.repo`（少了大括号）
  - `${a.${b}}`（嵌套）
- 预期：记录每种的实际识别结果
- 失败判定：识别出一堆垃圾条目

### PMT-13 · 预览 tab 的文案是否过期

- 类型：可解释性
- 操作：切到「预览」tab
- 当前文案：「预览要用一次真实运行的上下文替换变量。等 AI 节点接上 ACP 并跑过一次后，这里会显示替换后的完整提示词与 token 估算。」
- 判定：
  - **M3 已交付**，AI 节点已走真实 ACP 会话
  - 跑一条含 AI 节点的工作流（**用 `acp.codex`**），再回来看这个 tab
  - 仍显示那句话 → **文案过期，是缺陷**
  - 显示了预览 → 验证 **Secret 没有被展开成明文**
    （抄送 [B3](personas/B3-安全与可解释性.md)）

### PMT-14 · 版本 tab

- 类型：功能 / 可解释性
- 操作：
  1. 对一个提示词保存三次新版本
  2. 切到「版本」tab
- 预期：
  1. 第一条是「vN · 当前」，带更新时间
  2. 下面列出历史版本，每条带「<时间> · <谁改的>」
  3. 从没改过时显示「还没有改过。保存新版本之后，被替换掉的那份会留在这里。」
  4. 底部：「运行记录会引用当时的提示词版本，历史结果始终可解释。」
  5. **保存新版本后，这个 tab 立刻多一条**（不需要刷新页面）
- 失败判定：只显示当前版本——那么底部那句「历史结果始终可解释」就是空的

### PMT-15 · 历史版本能不能看内容 / 回滚

- 类型：体验
- 操作：点某个历史版本条目
- 预期：**记录实际行为**——能点吗？点了给什么？
- 说明：用户看到「v3」的第一反应是「v3 长什么样」「能不能回到 v3」。
  当前实现只是列表。工作流的版本抽屉有 Diff 与回滚，这里有吗？
  没有的话记进**建议**（图纸里那一页画了什么？去核对）。

### PMT-16 · 复制提示词

- 类型：功能
- 操作：点「复制」
- 预期：出现「<原名> 副本」，内容相同，**不是内置**（可编辑可删）

### PMT-17 · 删除与二次确认

- 类型：功能 / 边界
- 操作：同 [11](11-Agent角色.md) AGT-16 的流程
- 预期：
  1. 内置条目**没有**删除按钮
  2. 非内置的点「删除」变「确认删除」
  3. 切换到别的条目再回来，确认态**被清掉**
- 失败判定：确认态残留

### PMT-18 · 分段内容的极端输入

- 类型：边界
- 操作：
  1. 某段粘贴 5 万字
  2. 某段写 `<script>alert(1)</script>`
  3. 某段全是换行
  4. 段标题写 100 个字
- 预期：
  1. textarea 撑开但页面仍可用，底部按钮够得着
  2. 脚本原样显示为文本
  3. 标题过长时布局不破（截断要有 title）
- 失败判定：弹窗；或布局被撑破

### PMT-19 · 空分段能不能保存

- 类型：边界
- 操作：把所有分段的正文都清空 → 保存
- 预期：**存储层拒收空分段**（产品规则），界面显示可理解的错误
- 失败判定：存进去了一个空提示词

### PMT-20 · 三问清点

- 类型：体验
- 操作：对这些做三问：
  左栏条目的「N 段 · N 变量」、
  变量表里的变量名（想点它跳到正文里那个位置）、
  变量表的「运行时来源」（想知道具体从哪来）、
  版本 tab 的历史条目（想看内容、想回滚）、
  底部那句「系统调用 AI 的每一处都在这里」（想知道**这一条**用在哪）
- 重点：**「这条提示词用在哪」**——
  底部说它涵盖节点、⌘K 协作、记忆提议、通知与失败归因五处，
  那么选中一条时，界面告诉用户它属于哪一处了吗？
