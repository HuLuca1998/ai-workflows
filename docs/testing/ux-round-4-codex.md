## 第一部分：逐条复测

### 1. 🟡 主管 AI：取消回执稳定，但简单问答 90 秒仍未完成

复现步骤：

1. 在概览页点击“询问 AI”。
2. 选择“UI 登记的模型 1785211220166”。
3. 输入：“请只用两句话回答：我点‘新建工作流’后，在没有编辑和保存的情况下，页面显示的草稿版本是 rev0 还是 rev1？这个空草稿是否已经保存？”
4. 点击“发送”，持续等待 90 秒。
5. 另开一个新的浏览器上下文，再发送“请用一句话解释空工作流是什么。”，1.2 秒后点击“取消”，再等待 1.8 秒。

实际结果：

- 第一条请求在 90 秒内没有完成，输入区仍处于等待状态。与第三轮 20.1 秒相比，这次至少不能证明速度已有改善；为了避免无限占用，测试上下文在 90 秒后结束。
- 由于没有收到回答，第三轮曾出现的 `rev0` 被说成 `rev1` 这条准确性问题本轮无法判定是否修好。
- 取消操作约 1.8 秒后恢复为可发送状态，消息下方清楚显示“等待 1 秒后已取消”。取消回执仍然正常。

判断：取消链路已修复；等待时间仍明显妨碍使用，所以整体仍是部分修复。

### 2. 主管 AI 模型下拉：保持已修复，本轮不重复测试

第三轮已经逐页统计模型页的 71 条启用项，并确认主管 AI 下拉恰好 71 项且包含三条第二页基线模型。本轮遵照“已经修好的不用再花时间”，没有重复同一路径。

### 3. 🟡 空草稿立即落库：仍存在

复现步骤：

1. 在概览页点击“新建工作流”。
2. 进入编辑器后不改名、不拖节点、不点保存。
3. 观察标题、版本、保存状态和节点数。
4. 用只读 SQLite 按 URL 中的工作流 ID 查询 `workflow` 表。

实际结果：页面进入 `http://localhost:5173/editor/wf_146b4e20f8193050` 后立即显示：

```text

草稿 · rev0
1 个问题 · 0 节点 0 连接
```

数据库已经存在：


判断：行为与第三轮一致。上一轮处理说明已经明确选择保留该工程行为，因此这里只记录“仍存在”，不作为新回归。

### 4. 🟡 提示词变量：插入焦点已修复，登记链路仍未闭环

复现步骤：

1. 进入“提示词库”，搜索并打开“Codex Round 2 提示词 1785222114277”。
2. 在 ROLE 旁点击“插入变量”，不再点击正文，直接键入 `round4`。
3. 切换到“变量”页，检查 `${input.topic}` 一行及页面可操作控件。

实际结果：

- 变量页仍显示 `${input.topic} / 未登记 / 留空并记录`。
- 变量页除“模板 / 变量 / 预览 / 版本”页签和详情级复制、删除、保存外，没有登记变量、选择运行时来源或调整缺失策略的输入控件。

判断：插入动作已经顺手；变量发现之后仍无法在此处完成登记，整体是部分修复。

## 第二部分：自由使用——从失败运行定位问题

本轮换到“执行记录”，没有重复第三轮的 Agent 创建主路径。我实际完成了以下操作：

1. 等待运行列表加载完成，搜索“UI 测试 · 失败”；当时匹配 81 条，第一页显示 50 条。
2. 选择 `2026/7/28 17:59:35` 的失败运行，Run ID 为 `run_4cc47627654b9850`。
3. 查看节点进度、失败摘要、事件流、产物和对话三个页签。
4. 再用完整 Run ID 搜索，结果收窄为唯一一条。
5. 另选一条 `2026/7/28 17:05:41` 的待审批运行，查看审批卡片与事件流，但没有批准、拒绝或取消它。
6. 在失败运行点击“导出诊断包”。

顺畅的部分：

- 失败摘要同时给出节点名、`attempt 1 · 0s`、退出码 7 和“出错细节”，不用在长事件流里自己拼根因。
- 节点进度能看出入口已完成、脚本节点失败；事件流从 `run.created`、`run.preflight_passed` 一直到 `node.failed`、`run.failed`，时间顺序清楚。
- 产物页列出 `stderr.log / 13 B / boom`，并明确给出产物目录；敏感信息脱敏说明也在同一块视线内。
- 失败页把“从失败节点重试 / 回到最近审批点改选择 / 用相同参数重跑 / 导出诊断包”并排给出，恢复动作很好找。
- 完整 Run ID 能直接把 81 条同名运行缩到唯一结果，适合从日志或同事消息反查。
- 待审批运行会显示具体节点、Run ID、“批准 / 拒绝 / 取消运行”和 `approval.requested` 事件；即使不执行决策，也能先判断自己在批准什么。

### 10. 🟢 对话空状态暴露内部里程碑名“M3”

2. 点击“对话”。

影响：后半句已经能解释当前运行为什么为空；`M3` 更像内部项目阶段名，对普通用户没有帮助。删掉括号内容即可更自然。

## 总体感受

第三轮最危险的 Agent 静默数据丢失已经修好，版本历史和大列表搜索也都闭环；这几项修复能在刷新后稳定观察到，不只是按钮层面的变化。提示词“插入变量”终于符合连续输入习惯。

目前最明显的断点是 Agent 工具白名单：页面已经摆出“+ 添加”，但操作没有任何结果，让权限配置看起来接近完成却仍卡在实际调用工具之前。主管 AI 的取消体验可靠，但简单问题 90 秒无答仍不足以作为日常帮助入口。

执行记录则是本轮体验最好的一块：同名搜索、Run ID 精确定位、失败摘要、事件流、产物和恢复动作之间衔接清楚。诊断导出的命名与落点、对话空状态里的内部术语属于可收尾的体验细节。
