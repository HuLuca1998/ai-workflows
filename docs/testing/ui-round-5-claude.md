## 第二个大发现：「新增节点类型不改 UI 代码」不成立

这是 CLAUDE.md 明写的核心设计承诺，B1 用最硬的办法验了——
**往契约里加一个真的节点类型，configSchema 混入 9 种字段形状，一行 UI 代码都不改**，
然后用真实浏览器看结果。

**好消息**：七种控件够用。9 种字段形状**全部正确渲染、可编辑、保存成功、控制台零错误**，
`SchemaField.tsx` 与 `NodeConfigDialog.tsx` 确实一行都不用改——这两个文件的承诺兑现了。

**坏消息**：问题出在它们之外的**三张按节点类型穷举的表**：

| 文件:行              | 表       | 加节点类型后                    |
| -------------------- | -------- | ------------------------------- |
| `nodeDefaults.ts:12` | `TITLES` | `error TS2741`                  |
| `nodeDefaults.ts:36` | `SEEDS`  | `error TS2741` **且运行时也坏** |
| `nodeVisuals.ts:31`  | `ICONS`  | `error TS2741`                  |

`Record<NodeType, X>` 要求每个键都在，所以这三处是**强制**的，CI 直接打回。
更糟的是运行期——Vite 不做类型检查，界面照样起得来，但**节点拖不进画布**：

```
对照组 notify（SEEDS 里有条目）      节点数 3 → 4   错误提示 []
实验组 drift.probe2（SEEDS 里没有）  节点数 4 → 4   错误提示 ["第 1 个操作的节点配置不合法"]
```

**用户看到的是一句「节点配置不合法」，而他什么都还没填。**

按 CLAUDE.md 自己的判据（「如果发现必须改 UI，说明 Schema 表达力不够，那才是要解决的问题」）
逐张表看：

- `TITLES` **完全冗余**——`titleFor()` 的兜底本来就是 `getNodeDefinition(type).title`
- `SEEDS` **部分冗余**——可选字段的默认值 Zod 的 `.default()` 能表达，
  真正缺的是「必填字段的占位值」，`NodeDefinition` 里没有字段能表达它
- `ICONS` **完全无法表达**——`NodeDefinition` 没有 `icon` 字段，
  新节点在节点库里显示成一个通用圆圈，与其余 16 条格格不入

还有第四份穷举清单在契约里：长文本靠**字段名白名单**判定
（`fields.ts:38` 的 `LONG_TEXT_KEYS`）。同一个弹层里的 A/B 对照——
`promptTemplate` 与 `script` 的 Zod 类型完全一样（都是 `z.string()`），
只因为名字不在白名单里，前者渲染成 **34px 高的单行 input**，用户写不了多行提示词。

## 关于「拖动卡」——没能复现

你反馈过「编辑流程的时候发现拖动节点有点卡」。这一轮在 Chromium 下测不出来：

| 规模     | 平均帧率 | 最长帧     | 掉帧占比 |
| -------- | -------- | ---------- | -------- |
| 10 节点  | 74 fps   | 25 ms      | 0%       |
| 50 节点  | 71 fps   | 53 ms      | 2%       |
| 200 节点 | 66 fps   | **121 ms** | 2%       |

三个还没排除的解释：

1. **桌面形态跑的是 WKWebView，没测过** —— 你实际用的是那个形态，
   `docs/ROADMAP.md` 里也写着「WKWebView 侧待补」。**要定论必须在桌面壳里测**
2. 200 节点时那一次 121 ms 长帧（多半是松手落库那一下）
3. 体感可能来自别处：打开大图的首次渲染、缩到 35%、框选整体拖

**这条既不算 PASS 也不算 FAIL，算「没能复现」。**

   `supervisor.ask` 声明只读却写库（9）

   结构化错误造出来了，一路丢到界面只剩一句话
