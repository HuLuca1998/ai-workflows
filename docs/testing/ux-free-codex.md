# AI Workflows 自由 UX 体验记录

测试时间：2026-07-28（Asia/Singapore）

入口：`http://localhost:5173`

视口：1440 × 900，全新 Playwright 浏览器上下文

我把自己当成第一次打开应用、想尽快跑通一个最简单工作流的用户。全程只操作页面，没有阅读实现代码，也没有重启前后端服务。

## 总体感受

这是一个“核心骨架已经能跑，但首次使用闭环还没有接上”的产品。

编辑器、发布前校验、运行前 Dry Run 和运行详情已经连成了一条真实可用的主链路。我最终成功创建了一个只有“入口设置”节点的工作流，保存、发布为 v1、运行，并在执行记录里看到完整的 7 条事件。尤其是运行前明确展示“3 项通过 · 0 项缺失”，运行后按时间展示 `run.created`、`run.preflight_passed`、`node.succeeded` 等事件，让我对系统正在做什么很有信心。

但作为新用户，我首先被顶部连续三个状态提醒：“尚未授权工作目录”“未设置权限档”“环境尚未检查”。自然地进入“首次配置”后，却没有任何配置控件；“设置与环境”也没有补救入口。奇怪的是，绕过这些提醒后，最小工作流又确实能用默认目录成功运行。页面表达出的阻塞程度与实际能力不一致，使我一开始不知道自己究竟能不能继续。

## 我实际走过的路径

1. 打开首页。顶部显示尚未授权、未设置权限档、环境未检查；首页同时已有 1163 个工作流、今日 466 次运行。
2. 点击左侧“首次配置”。页面只有“装好即可用”“这一屏在 M5 · 可交付 落地。当前是 M0 应用外壳阶段。”，没有输入框、按钮或下一步。
3. 点击“设置与环境”寻找替代入口。页面只有环境说明、空的能力表头和版本说明，仍没有检查、授权或设置权限档的操作。
4. 回到首页点击“新建工作流”。应用直接创建并进入“未命名工作流 1164”；之后我的其他探索点击也留下了新的未命名草稿。
5. 将“入口设置”从节点库拖到画布。页面立刻从“1 个问题 · 0 节点”变成“校验通过 · 1 节点 0 连接”。双击节点后，配置面板提供“配置 / 输入输出 / 权限与能力 / 重试与超时”四组内容，并明确说明“改动只影响草稿”。
6. 未保存时先点“发布版本”，页面给出“有未保存的改动。请先保存草稿，再发布版本。”；随后保存草稿并成功发布 v1。
7. 点击“运行”。启动面板说明该流程不需要参数，默认工作目录是 `/Users/luca/aiwf-local-test/data/runs`，Dry Run 的图结构、可达性和工作目录三项全部通过。
8. 点击“开始运行”。页面跳到执行记录，刚创建的“未命名工作流 1202”显示成功。搜索它时，输入文字不会立即筛选；按 Enter 后从 475 条历史缩到 1 条。点开后看到 1 个节点完成和 7 条事件。
9. 点击顶部“询问 AI”，保留默认模型，提问“第一次使用时，我应该怎样创建并运行一个最简单的工作流？”。界面进入“正在想… / 思考中”，连续等待 30 秒仍没有回复、超时提示或取消入口；控制台也没有可见错误。

## 做得好的地方

### 编辑器的状态反馈很及时

拖入入口节点后，顶部校验状态、节点数和连接数马上更新。底部还直接提示双击编辑、右键菜单、端口连线、框选与全选快捷键。第一次进入复杂画布时，这些就地提示比单独的帮助文档更有效。

### 草稿、发布、运行的边界比较清楚

节点配置明确写着“改动保存到草稿，不影响已发布版本”；未保存就发布时也会直接告诉我应该先做什么。运行弹窗允许在“草稿 rev1”和“v1”之间选择，并解释运行记录保存的是启动那一刻的修订号。这里的产品语言很扎实。

### Dry Run 和运行详情很有可信度

运行前不是只给一个“可以运行”，而是逐项展示图结构、节点可达性、工作目录。运行详情则把节点进度与事件流放在一起，事件名、中文解释、时间和 Run ID 都能看到，定位失败时应该会很好用。

### 主管 AI 的授权范围表达得好

抽屉底部明确列出本次会话获得的 `workflow:read`、`workflow:write-draft`、`memory:read`，并明确说明“发布与运行未授权”。即使实际请求没有返回，这种权限透明度仍然让我感到安全。

## 遇到的问题

### P0：执行记录列表直接展示完整 Secret，与详情页的脱敏承诺矛盾

复现步骤：

1. 从左侧进入“执行记录”。
2. 保持“全部”筛选，向下查看 2026/7/28 05:44:06 的“脱敏验证”运行。
3. 观察列表摘要。

实际结果：列表直接显示了完整的 `apiKey=sk-proj-…` 值（测试时首尾及中间字符都可见，并非星号或截断）。而我点开自己的运行详情时，页面底部明确写着“Secret 值在写入事件存储前已脱敏，界面不提供绕过查看”。这两处表现互相冲突。

影响：运行参数很可能包含真实 API Key。即使详情事件存储做了脱敏，只要列表摘要仍能泄露，用户就不能相信“界面不提供绕过查看”的承诺。建议把所有进入列表摘要、搜索索引和详情的参数统一走同一套敏感值识别与脱敏规则，并补一条端到端用例。

### P1：首次配置是死路，设置页也没有替代入口

复现步骤：

1. 用新浏览器上下文打开首页。
2. 看到“尚未授权工作目录 / 未设置权限档 / 环境尚未检查”。
3. 点击左侧“首次配置”。
4. 再点击“设置与环境”。

实际结果：“首次配置”只有阶段占位文案，没有任何控件；“设置与环境”也只有说明、空表头和版本文字。用户无法完成页面要求的目录授权、权限档选择和环境检查。

影响：这是新用户最自然的第一条路径，却没有下一步。更困惑的是，绕过配置后最小流程仍能使用默认目录运行成功。建议在功能未完成前至少提供明确的“暂不配置，使用默认目录继续”主按钮，并把不可用状态改成说明，而不是像待办事项一样悬在所有页面顶部。

### P1：主管 AI 请求 30 秒无结果，也没有失败或取消反馈

复现步骤：

1. 在首页点击顶部“询问 AI”。
2. 保留默认选中的模型。
3. 输入“第一次使用时，我应该怎样创建并运行一个最简单的工作流？”。
4. 点击“发送”，等待 30 秒。

实际结果：消息已出现在会话中，状态一直是“正在想… / 思考中”；“发送”按钮消失，30 秒内没有回复、错误、超时倒计时、重试或取消操作。页面控制台也没有可见错误。

影响：这是首页最醒目的求助入口，而我恰好在首次配置受阻后最需要它。建议展示请求阶段和耗时，提供取消按钮，并在模型不可用、后端无响应或达到超时时给出可操作的错误提示。

### P2：点击“新建工作流”立即落一条持久草稿，探索成本会变成数据垃圾

复现步骤：

1. 在首页点击“新建工作流”。
2. 不做编辑，直接离开编辑器回到首页。
3. 查看工作流列表。

实际结果：点击后没有命名或确认步骤，应用立即生成“未命名工作流 N”；我仅为了查看编辑器而产生的草稿，之后仍出现在首页列表中。我的探索过程中实际看到了自己留下的“未命名工作流 1164、1165、1166”等条目。

影响：新用户试错几次就会污染首页，而且列表内没有显眼的批量清理入口。可以考虑先进入未落库的临时编辑状态，在第一次有效修改或用户确认名称后再创建；或者离开空白流程时询问是否丢弃。

### P2：搜索必须按 Enter 才生效，但界面没有提示

复现步骤：

1. 进入“执行记录”，在“搜索工作流、参数或 Run ID”中输入 `未命名工作流 1202`。
2. 等待 2.5 秒，观察列表。
3. 按 Enter，再观察列表。

实际结果：输入后列表仍保持 475 条历史，连完全不相关的 `boom` 记录也全部存在；按 Enter 后才缩成 1 条。输入框旁没有搜索按钮，placeholder 也没有说明需要回车。

影响：常见预期是此类列表搜索会即时过滤；没有变化时很像搜索失效。若有意采用提交式搜索，建议增加搜索按钮或在 placeholder 中写“输入后按 Enter”。

### P2：大量历史数据一次性铺满页面，首页和执行记录都很难扫读

复现步骤：

1. 打开首页，观察“本地优先 · 1227 个工作流”的列表。
2. 进入“执行记录”，保持“全部”。

实际结果：首页把上千条工作流连续铺开；执行记录初始也一次展示 475 条历史，浏览器中生成了 483 个按钮。虽然页面仍能使用，但首次进入时信息量巨大，真正关心的流程和运行很难找到。

影响：随着真实使用时间增长，这会变成日常问题。建议分页或虚拟列表，默认只渲染最近一段，并提供清晰的排序、时间范围和更强的筛选。

## 如果只做三件事

1. 先修复执行记录摘要的 Secret 泄露，并用同一套规则覆盖列表、搜索与详情。
2. 把“首次配置”做成可完成的流程，或明确提供使用安全默认值继续的路径。
3. 给主管 AI 请求加入超时、失败和取消反馈，确保它能在新用户最需要帮助时给出确定结果。

做到这三点后，现有编辑器—发布—运行—追踪这条主链路的优点会更容易被用户真正感受到。
