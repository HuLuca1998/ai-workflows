# AI Workflows UX 第三轮复测

测试时间：2026-07-28（Asia/Singapore）

入口：`http://localhost:5173`

主要视口：`1440 × 900`；布局专项：`1090 × 1040`、`1280 × 620`

本轮使用全新浏览器会话实际点击、输入、翻页、拖动和键盘操作；仅用 SQLite 只读查询交叉核对列表条数，没有阅读实现代码，也没有重启前后端。测试期间后台数据仍在持续增加，因此工作流和运行的绝对总数前后有变化；下文的翻页去重结论都取自同一次连续遍历中的页面快照。

## 第一部分：6 个问题逐条复测

### 1. Secret 泄露：仍存在

复现步骤：

1. 进入“执行记录”。
2. 在搜索框输入“脱敏验证”，等待 2.8 秒后按 Enter。
3. 查看唯一一条结果的参数摘要。

实际结果：列表中的值从 `sk-proj-` 开头到末尾都可见，不是掩码、截断或敏感值占位符；本报告主动记为 `apiKey=sk-proj-…7890`，避免再次传播完整值。

### 2. 首次配置死路：仍存在

复现步骤：

1. 打开“首次配置”。
2. 尝试查找目录授权、权限档选择或继续按钮。
3. 再进入“设置与环境”寻找替代入口。

实际结果：“首次配置”仍只有“装好即可用”“这一屏在 M5 · 可交付 落地。当前是 M0 应用外壳阶段。”；“设置与环境”只有环境说明、能力表和版本信息，没有可完成配置的控件。

此外，“设置与环境”本轮直接显示“`env.health` 的返回值不合契约”，但没有重试、诊断详情或修复入口。

### 3. 主管 AI 长时间无结果：部分修复

复现步骤：

1. 首页点击“询问 AI”，保留默认模型。
2. 输入“第一次使用时，我应该怎样创建并运行一个最简单的工作流？”并发送。
3. 持续观察到 44 秒，再点击“取消”。

实际结果：5 秒后出现“正在想…已等待 5 秒”，计时会持续增长，且有可点击的“取消”按钮；到 44 秒仍没有回复、失败、超时或重试。点击取消后等待状态消失，但界面没有“已取消”或取消原因。

判断：上轮“完全没有进度和取消入口”的问题已修；请求没有自动收敛、取消结果不明确的问题仍在。

### 4. 空白工作流立即持久化：仍存在

复现步骤：

1. 首页记下分页总数 1,484。
2. 点击“新建工作流”，不拖节点、不改名称、不保存。
3. 直接返回首页。

实际结果：点击后立即进入 `/editor/wf_366ed148449a8087`，标题为“未命名工作流 51”、状态为“草稿 · rev0 / 已保存”。返回首页后该 ID 仍是第一条，总数变为 1,485。

### 5. 执行记录搜索必须按 Enter：仍存在

复现步骤：

1. 进入“执行记录”，保持“全部”。
2. 输入“脱敏验证”，等待 2.8 秒。
3. 观察仍为 50 条后按 Enter。

实际结果：等待不会触发搜索；按 Enter 后才显示“历史 · 1”。输入框旁没有搜索按钮，placeholder 也没有回车提示。

### 6. 大列表一次铺满：部分修复

工作流首页不再渲染一千多行，执行记录首屏也只放 50 条，页面体量明显下降。但“分页存在”不等于“历史可访问”：执行记录所有后续页都重复首页 50 条，模型和 Agent 则只显示前 50 条且没有分页控件。详细结果见下一节。

### 工作流：翻页本身正确，搜索和状态筛选只作用于当前页

基础翻页实测：

1. 从第一页连续点击“下一页”直到末页。
2. 记录每页工作流 ID、区间文字和行数。
3. 对 29 页 ID 去重。

结果：`1–50`、`51–100`……`1351–1400`、`1401–1424` 的边界连续；1,424 个 ID 全部唯一，没有页间重复或缺口；第一页“上一页”和末页“下一页”正确禁用。

筛选实测：

1. 停在第 29 页，点击“失败”。
2. 页码仍显示“1401 – 1424 / 共 1,424 条”，页面只剩当前页内的一条失败记录。
3. 切回“全部”，在第 29 页搜索第一页已确认存在的“搜索目标 alpha 1785212647633”。

结果：页面提示“当前筛选下没有工作流”，页码和总数仍是 1,424；并没有回到第一页，也没有在全量数据中搜索。也就是说，搜索和状态筛选是在服务器已经切好的当前 50 条上二次过滤，筛选后的总数不正确。

### 运行：页码在走，数据没有走

复现步骤：

1. “执行记录”保持“全部”，记录第一页首尾 Run ID。
2. 连续点击“下一页”到末页。
3. 比较每页实际渲染的 Run ID 和行数。

实际结果：页码依次变成 `1–50 / 555`、`51–100 / 555`……`551–555 / 555`，但 12 页的首尾 ID 完全相同，每页都是第一页的 50 条。末页“下一页”会禁用，可真正的末 505 条运行完全不可见。

筛选的页码状态本身较好：在末页点击“失败”会回到 `1–50 / 共 60 条`，总数也会变化；但进入失败结果第 2 页后，标签写着 `51–60`，实际仍重复显示 50 条。因此筛选重置没有修复底层换页问题。

搜索到唯一结果后分页控件会隐藏，这一条符合“一页装得下时隐藏”的要求。

### 记忆、提示词、模型、Agent

- 记忆为 0 条，空状态正常且不显示分页。
- 提示词在 42/44 条时正常隐藏分页，没有为了单页数据保留无效控件。
- 模型与 Agent 都刚好只渲染 50 条。页面没有“下一页”、总数或搜索入口；只读数据库在同一时刻分别有 56 个模型和 97 个 Agent，说明这不是“恰好一页”，而是超出 50 条的内容被静默截断。

### 分隔条交互

三页的分隔条都有 `role=separator`、可聚焦、带当前宽度值，以下操作均亲自执行通过：

- **拖动：** Agent 从 250 拖到 374；提示词从 266 拖到上限 560；模型从 262 拖到上限 560，左右宽度立即变化。
- **记住：** 拖动后离开页面再返回，Agent 仍为 374、提示词仍为 560、模型仍为 560。
- **双击复位：** Agent 回到 250，提示词回到 266，模型回到 262。
- **键盘：** 聚焦后按 `ArrowRight` 都增加 16 px（如 250→266），按 `ArrowLeft` 回到原值；变化也会保存。

## 第四部分：新发现的问题

### 🔴 执行记录分页只改页码，不换数据

复现步骤：

1. 进入“执行记录”，记录第一页首条和末条。
2. 点击“下一页”两次，再一路翻到末页。
3. 对照页面上的区间与实际条目。

实际结果：区间不断前进，50 条记录却始终与第一页完全相同；末页声称只有 5 条时仍显示 50 条。除第一页之外的历史运行无法浏览。

### 🔴 模型和 Agent 超过 50 条后被静默截断

复现步骤：

1. 分别进入“模型”和“Agent 角色”。
2. 滚到左栏底部，寻找分页或更多加载入口。
3. 用数据库只读计数与页面条数交叉核对。

实际结果：两页都固定显示 50 条且无分页；同一时刻数据库分别为模型 56 条、Agent 97 条。用户没有任何办法从这两个页面访问其余条目。

### 🟡 工作流筛选和搜索只过滤当前页，总数不更新

复现步骤：

1. 将工作流翻到最后一页。
2. 点击“失败”，或搜索一个只存在于第一页的已知名称。

实际结果：页码仍停在最后一页，总数仍是全部工作流总数；状态筛选只留下当前页命中的行，搜索则错误显示没有结果。

### 🟡 首页“本地优先 · N 个工作流”显示的是当前页行数

复现步骤：

1. 首页第一页观察标题，显示“本地优先 · 50 个工作流”。
2. 翻到当时只有 24 条的最后一页。

实际结果：标题变成“本地优先 · 24 个工作流”，而分页总数是 1,424。这个文案看起来像全量统计，实际跟着当前页变化。

### 🟡 环境健康页暴露内部契约错误，但没有恢复动作

复现步骤：

1. 打开“设置与环境”。
2. 查看“运行环境健康”区域。

实际结果：页面直接显示“`env.health` 的返回值不合契约”，能力表为空；没有重试、展开错误详情或回到首次配置的操作。

### 🟢 本轮未发现新的低优先级问题

分栏高度、独立滚动、拖动记忆、双击复位和键盘调整均达到本轮要求；单页分页控件隐藏也在记忆、提示词和单条搜索结果中正常工作。
