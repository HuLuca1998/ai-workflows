## 新发现的问题

### 🔴 走不通

#### R1. Agent 页加载完成前打开“新建角色”，表单永久没有模型，无法创建

- 现象：模型接口返回成功，但新建表单不会吸收稍后到达的模型数据。
- 复现步骤：
  1. fresh load 打开 `/agents`；
  2. 页面一出现就立即点“新建角色”，不要先等待列表和模型请求稳定；
  3. 查看“模型”下拉和“创建”按钮；
  4. 等待 10 秒，再次查看。
- 期望：加载期间给出“正在读取模型”，数据到达后自动选中第一条可用模型；或者在依赖就绪前暂时禁用“新建角色”。
- 实际：刚打开时模型 option 数为 0，10 秒后仍为 0，“创建”一直 disabled。同期浏览器网络面板中 `model_list` 返回 200 且包含多条已启用模型。若先在 Agent 页等待模型加载完再点“新建角色”，则能看到模型，说明这是可稳定触发的时序竞态。

#### R2. 启动表单无视 JSON Schema 类型，非法 integer / boolean / enum 仍能成功运行

- 现象：入口 Schema 的字段类型与约束被丢掉，所有参数都退化为任意文本。
- 复现步骤：
  1. 创建只有入口节点的工作流；入口 `inputSchema` 定义三个必填字段：integer `count`（minimum=1）、boolean `flag`、枚举 `mode`（`safe` / `fast`）；
  2. 在编辑器点“运行”；
  3. 查看三个控件的 HTML 类型；
  4. 分别填 `不是数字`、`也不是布尔值`、`不存在的模式`，点“开始运行”。
- 期望：integer 用数字输入并校验范围，boolean 用开关/复选框，enum 用下拉；非法值应留在表单并指出具体错误。
- 实际：三个控件全部是 `INPUT type="text"`；上述三个非法值被接受，运行 `run_eddfb93f958f21a2` 最终状态为 succeeded。用户无法保证传给后续节点的参数类型。

#### R3. 已完成的长事件流硬截断在 200 条，缺少最终事件且没有继续加载入口

- 现象：执行记录没有展示完整审计轨迹。
- 复现步骤：
  1. 创建入口 + 105 个 Shell 节点的顺序链并运行至 succeeded；
  2. 等运行完成后再打开 `/runs?run=run_87468a64d4ce3f5a`；
  3. 查看事件计数并滚到事件流底部；
  4. 用后端 `run_events`（limit 500）或只读数据库核对该 Run 的事件总数。
- 期望：自动分批加载全部事件，或在第 200 条后提供“加载更多”，最终能看到最后几个节点和 `run.succeeded`。
- 实际：后端及数据库均为 217 条，页面固定显示“200 条事件”，没有“加载更多”。页面最后一条是“可读节点 96”的 `node.succeeded`；节点 97–104 和最终 `run.succeeded` 全部缺失。

### 🟡 能用但别扭

#### Y1. 必填参数为空时只有红框，没有中文错误和无障碍错误语义

- 现象：空值会被挡住，但用户和读屏都难以知道为什么没有启动。
- 复现步骤：
  1. 打开上述含 3 个必填参数的启动表单；
  2. 三项都留空，点“开始运行”；
  3. 查看表单文字和字段属性。
- 期望：每项显示“数量不能为空”等中文错误，并设置 `aria-invalid="true"`，最好把焦点移到第一项。
- 实际：三个 input 只有内部 `data-missing="true"`，`aria-invalid` 数量为 0；页面没有“不能为空 / 必填 / 请填写”等可见错误文本。

#### Y2. 撤销 / 重做完全不可用，⌘Z 也不生效

- 现象：常规编辑器的纠错手段缺失。
- 复现步骤：
  1. 打开含 3 个节点的工作流；
  2. 右键 Shell 节点，点“复制”，确认节点数从 3 变 4；
  3. 查看工具栏的撤销、重做按钮，再按 `⌘Z`。
- 期望：撤销恢复到 3 个节点，重做可再次恢复到 4 个。
- 实际：按钮无障碍名称直接写着“撤销（待实现）/ 重做（待实现）”且均 disabled；按 `⌘Z` 后节点仍为 4。

#### Y3. 编辑器明示的 ⌘A 不生效，⌘C / ⌘V 也没有复制粘贴

- 现象：底部状态栏明确写“⌘A 全选”，但实际按键没有任何反馈；标准复制粘贴快捷键也不可用。
- 复现步骤：
  1. 打开含两个节点的编辑器，先点画布空白；
  2. 按 `⌘A`，观察底部选择状态；
  3. 单击一个节点后依次按 `⌘C`、`⌘V`，观察节点数。
- 期望：`⌘A` 后显示“已选 2 个”；复制粘贴后出现一个偏移副本。
- 实际：`⌘A` 后仍显示“未选中”；`⌘C`、`⌘V` 后节点数不变。右键菜单的“复制”可以正常创建副本，因此键盘与鼠标能力不一致。

#### Y4. 失败横幅已改用标题，但节点进度和事件流仍暴露内部 ID

- 现象：同一运行详情内部，节点命名规则不一致。
- 复现步骤：
  1. 打开长事件运行 `run_87468a64d4ce3f5a`；该图的节点标题为“长流入口”“可读节点 0…”、内部 ID 为 `entry_long_retest`、`internal_long_0`…；
  2. 查看中栏“节点进度”的节点名；
  3. 查看右栏事件流每条事件后的节点标签。
- 期望：中栏和事件流优先显示画布标题，技术 ID 可作为次要信息或 tooltip。
- 实际：中栏依次显示 `entry_long_retest`、`internal_long_0`、`internal_long_1`；事件流同样显示内部 ID。只有失败横幅使用了用户标题。

#### Y5. 事件流没有任何事件类型 / 类别筛选

- 现象：长事件中无法只看失败、审批、节点或运行生命周期事件。
- 复现步骤：
  1. 打开任一有大量事件的运行详情；
  2. 切到“事件流”；
  3. 检查标签页附近和事件列表顶部的控件。
- 期望：至少可按运行 / 节点 / 审批 / 错误筛选，并能一键只看失败。
- 实际：只有“事件流 / 产物 / 对话”三级视图，事件筛选控件数量为 0；217 条事件只能线性浏览。

### 🟢 细节

本轮没有新增只影响视觉细节的问题；发现的问题均会影响操作完成度、参数正确性或运行记录的可解释性，因此归入红色或黄色。

## 总体评价

上一轮列出的 13 项中，11 项已完整修复，Agent 新建和停用引用模型 2 项为部分修复，模型 high 刷新问题本轮未再复现。主链路已经明显更可靠：真实连线、右键菜单、Shift 框选、Dry Run 对悬空节点的阻断、并行运行、取消运行、审批通过与拒绝，以及记忆提议的采纳/忽略、搜索和作用域筛选均已走通。当前最需要优先处理的是长事件流 200 条截断和启动参数类型不校验；前者会让审计记录不完整，后者会让“成功启动”建立在错误输入上。随后应补齐 Agent 新建时序保护与编辑器键盘/撤销能力，避免功能看似存在但在常见操作中失效。
