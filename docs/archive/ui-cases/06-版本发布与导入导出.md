# 06 · 版本发布与导入导出

版本抽屉从右侧滑入，460px。图纸「02 画布编辑器」的版本抽屉。

这一屏兑现两条核心承诺：**发布快照不可变**、**运行记录永远引用具体版本**。

## 概念先说清（测的时候别混）

| 概念     | 是什么                   | 变不变      | 界面上怎么显示   |
| -------- | ------------------------ | ----------- | ---------------- |
| 草稿 rev | 可变的工作副本，单调递增 | 每次保存 +1 | 「草稿 · revN」  |
| 版本 vN  | 不可变发布快照           | **永不变**  | 「vN」+ 配置哈希 |

**用户最容易混的就是这两个**——测「术语自解释」时重点看这里
（[F1 剧本 C4](personas/F1-界面与体验.md)）。

## 元素清单

| #   | 元素              | 内容                                                            | 能点吗     |
| --- | ----------------- | --------------------------------------------------------------- | ---------- |
| 1   | 头部标题          | 「版本历史」                                                    | 纯展示     |
| 2   | 头部副文本        | 「发布快照不可变，运行记录永远引用具体版本」                    | 纯展示     |
| 3   | 关闭              | `aria-label="关闭版本历史"`                                     | 应可点     |
| 4   | 当前草稿卡        | 「当前草稿 revN」+「有未保存改动」/「未发布」                   | **待验证** |
| 5   | 草稿说明          | 「N 节点 N 连接」（有改动时加「· 先保存草稿才能发布」）         | 纯展示     |
| 6   | 版本条目          | 「vN」+「最新」标记 + 时间 + 发布者 + 配置哈希前 12 位          | 应可点     |
| 7   | 空态              | 「还没有发布过版本。发布后这里会列出每个不可变快照。」          | 纯展示     |
| 8   | Diff 区           | 标题「vN → 当前草稿」+ 增删行                                   | **待验证** |
| 9   | 「导出此版本」    | 未选版本时禁用                                                  | 应可点     |
| 10  | 「回滚为草稿」    | 未选版本时禁用，title「先选一个版本」                           | 应可点     |
| 11  | 「发布草稿为 vN」 | 主按钮；有未保存改动时禁用，title「有未保存的改动，先保存草稿」 | 应可点     |
| 12  | 遮罩              | 抽屉外的区域                                                    | 点了关闭   |

## 用例

### VER-01 · 从未发布过时的空态

- 类型：功能
- 前置：新建一条工作流，加两个节点并保存
- 操作：点工具栏「版本」
- 预期：
  1. 抽屉从右侧滑入，宽 460px
  2. 头部两行文案一字不差
  3. 当前草稿卡显示「当前草稿 rev1」（或实际 rev）+「未发布」
  4. 说明显示「2 节点 1 连接」
  5. 版本列表区显示空态那句话
  6. 底部主按钮是「发布草稿为 v1」
  7. 「导出此版本」与「回滚为草稿」**禁用**
- 失败判定：空态没有说明；主按钮写的是 v0 或 v2

### VER-02 · 发布第一个版本

- 类型：功能
- 前置：图校验通过、已保存
- 操作：点「发布草稿为 v1」
- 预期：
  1. 抽屉关闭
  2. 再打开时，版本列表里有一条 v1，带「最新」标记
  3. 条目上有：发布时间、「发布者 <名字>」、「配置哈希 <12 位>」
  4. 工具栏的草稿标签从「草稿 · rev N」变成「草稿 · 基于 v1」
- 失败判定：发布了但列表里没有；哈希显示全长或空

### VER-03 · 有未保存改动时不能发布

- 类型：功能 / 边界
- 操作：
  1. 在画布上拖一个节点（不保存）
  2. 打开版本抽屉
- 预期：
  1. 当前草稿卡显示「有未保存改动」
  2. 说明里多一句「· 先保存草稿才能发布」
  3. 「发布草稿为 vN」**禁用**，title 是「有未保存的改动，先保存草稿」
- 失败判定：能发布（那会把未保存的改动排除在外，用户以为发的是眼前这份）

### VER-04 · 有校验错误时不能发布

- 类型：边界
- 操作：制造一个校验错误（如删掉 entry）→ 保存 → 点工具栏「发布版本」
- 预期：工具栏的「发布版本」按钮**禁用**
- 失败判定：发布出一个跑不起来的版本

### VER-05 · 发布快照不可变

- 类型：功能 / 可解释性（**核心承诺**）
- 操作：
  1. 发布 v1
  2. 回画布改动几个节点，保存
  3. 打开版本抽屉，选中 v1，看 Diff
- 预期：
  1. Diff 标题是「v1 → 当前草稿」
  2. Diff 里能看到你刚才的改动（增删行）
  3. **v1 本身没有变**——导出 v1 得到的是发布时那份图
- 失败判定：v1 的内容跟着草稿变了

### VER-06 · Diff 方向与内容

- 类型：功能
- 操作：在 v1 之后加一个节点、删一个节点、改一个配置，保存，再看 Diff
- 预期：
  1. 方向是「选中版本 → 当前草稿」
  2. 新增的显示为 `+` 行
  3. 删除的显示为 `−` 行
  4. 配置修改能看出来是哪个节点
  5. 没有差异时显示空 Diff 的说明而不是一片空白
- 失败判定：方向反了（把草稿当成旧的）

### VER-07 · 切换版本时 Diff 跟着变

- 类型：功能 / 边界
- 前置：已有 v1、v2、v3
- 操作：
  1. 点 v1 → 看 Diff
  2. 立刻点 v3 → 看 Diff
- 预期：
  1. 每次都显示「正在读取版本…」再显示 Diff
  2. 最终显示的是 **v3 → 当前草稿**（不能因为 v1 的请求后回来把 v3 的 Diff 盖掉）
  3. 选中的条目有 `data-selected` 标记
- 失败判定：快速切换后显示的是先选的那个（竞态）

### VER-08 · 导出此版本

- 类型：功能
- 操作：选中 v1 → 点「导出此版本」
- 预期：
  1. 浏览器下载一个 JSON 文件
  2. 文件名形如 `<工作流名>-v1.json`
  3. 内容是那个版本的图（节点、边、分组）
  4. **能被原样导入回来**（去 [02](02-概览与工作流首页.md) OVW-19 验证）
- 失败判定：导出的是当前草稿而不是选中版本

### VER-09 · 回滚为草稿

- 类型：功能（**注意它不是「撤销」**）
- 前置：v1 有 3 个节点；之后草稿改成了 5 个节点并发布成 v2
- 操作：选中 v1 → 点「回滚为草稿」
- 预期：
  1. 抽屉关闭
  2. 画布回到 v1 的样子（3 个节点）
  3. 草稿 rev **递增**（回滚是写了一个新的草稿修订，不是回退 rev）
  4. **v2 仍然在版本列表里**（回滚不删除任何版本）
  5. 原来那份草稿仍在修订历史里，没有丢
- 失败判定：v2 被删掉了；或 rev 倒退了

### VER-10 · 回滚前必须先选版本

- 类型：边界
- 操作：不选任何版本（新打开抽屉且列表为空时）→ 看「回滚为草稿」
- 预期：禁用，title「先选一个版本」
- 失败判定：可点且点了报错

### VER-11 · 「最新」标记只在最新那条上

- 类型：功能
- 前置：已有 v1、v2、v3
- 预期：只有 v3 带「最新」标记
- 失败判定：多条带标记；或标在 v1 上

### VER-12 · 关闭抽屉的三种方式

- 类型：功能
- 操作：
  1. 点右上角关闭按钮
  2. 点抽屉外的遮罩
  3. 焦点在抽屉内时按 Esc
- 预期：三种都关闭
- 失败判定：点遮罩关不掉；Esc 无效

### VER-13 · 点抽屉内部不会误关

- 类型：边界
- 操作：点抽屉内的空白区域
- 预期：抽屉不关（点击事件被 `stopPropagation` 拦住）
- 失败判定：点一下内容区就关了

### VER-14 · 读取版本失败时的表现

- 类型：边界
- 操作：断网后选一个版本
- 预期：
  1. Diff 区显示错误（`role="alert"`），用红色/删除行的样式
  2. 抽屉不崩
  3. 恢复网络后重新点该版本能成功
- 失败判定：整个抽屉白掉

### VER-15 · 发布之后运行记录引用的是版本

- 类型：可解释性
- 操作：
  1. 发布 v1 → 用启动表单选「v1」运行一次
  2. 改草稿 → 发布 v2
  3. 去执行记录看第一次那条运行
- 预期：那条运行引用的仍是 v1，且**图没有跟着变**
- 失败判定：运行记录显示 v2（详见 [B3 剧本 V7](personas/B3-安全与可解释性.md)）

### VER-16 · 导出 → 导入 → 图一致（往返测试）

- 类型：功能 / 边界
- 操作：
  1. 从版本抽屉导出 v1
  2. 回 `/` 导入那个文件
  3. 对比新工作流与原 v1 的节点数、连接数、分组数、每个节点的配置
- 预期：完全一致
- 失败判定：分组丢了；节点位置变了；配置里的某个字段被吃掉

### VER-17 · 配置哈希

- 类型：可解释性
- 操作：看版本条目上的「配置哈希 <12 位>」
- 预期：
  1. 显示的是前 12 位
  2. **同一份图发布两次，哈希相同**（试：发布 v1 → 不改任何东西再发布 v2）
  3. 改了图之后发布，哈希不同
- 说明：第 2 条要注意——不改任何东西时能不能发布？记录实际行为。

### VER-18 · 三问清点

- 类型：体验
- 操作：对这些做三问：
  当前草稿卡（#4，用户会想点它回到画布）、
  版本条目上的**配置哈希**（想复制它）、
  版本条目上的**发布者**（想知道是谁）、
  Diff 里的某一行（想点它跳到画布上对应的节点）
- 重点：**Diff 的行**——用户看到「+ 节点 X」时，
  第一反应是「哪个节点？让我看看」。点得动吗？
