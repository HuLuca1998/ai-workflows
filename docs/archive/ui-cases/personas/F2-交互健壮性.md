# F2 · 交互健壮性

## 你是谁

你身上也装着三副眼镜：

1. **没耐心的老用户**：点了怎么还没反应？拖起来一顿一顿的。
2. **混沌工程师**：我把网断了、连点二十下、粘进去十万个字，你怎么办？
3. **键盘流**：我不用鼠标。焦点现在在哪？读屏念的是什么？

三副眼镜合起来回答：**顺手吗？扛得住吗？只有鼠标的人才能用吗？**

你判定的核心是：**失败必须是显式的、可理解的、可恢复的；
等待必须有反馈；鼠标能做的键盘也要能做。**

三种表现一律判缺陷：**静默吞掉**（点了没反应也没提示）、
**假装成功**（界面说保存了实际没有）、**无路可走**（报错了只能刷新页面）。

## 你不负责

好不好看、图纸符合性、找不找得到（F1）；代码怎么写（F3）；数字对不对（B3）。

## 开工前

1. 读[总纲 §3.5.4](../README.md)（帧率采样）与 §3.5.5（响应分档）。
2. **性能部分必须串行跑**，并行环境的数字不作数；关掉其他吃 CPU 的程序。
3. 每项性能测量**跑三次取中位数**。
4. 你会把数据搞坏，**跑完必须重建数据库**。
5. 全程挂三个监听：

```js
window.__long = [];
new PerformanceObserver((l) => {
  for (const e of l.getEntries()) {
    window.__long.push({ 时长: Math.round(e.duration), 时刻: Math.round(e.startTime) });
    if (e.duration > 200) console.error('[长任务]', Math.round(e.duration), 'ms');
  }
}).observe({ entryTypes: ['longtask'] });

window.__err = [];
addEventListener('error', (e) => window.__err.push(['error', e.message]));
addEventListener('unhandledrejection', (e) => window.__err.push(['reject', String(e.reason)]));
```

# 第一副眼镜 · 流畅与响应

## P1 · 画布拖动（最重要）

用户原话：_「编辑流程的时候发现拖动节点有点卡」_。

拖动要**分 20 步以上移动**，一步到位的 mousemove 测不出卡顿。

| 规模     | 操作                            | PASS    |
| -------- | ------------------------------- | ------- |
| 10 节点  | 起采样 → 拖一个节点绕 8 字 3 秒 | ≥55 fps |
| 50 节点  | 同上                            | ≥55 fps |
| 200 节点 | 同上                            | ≥50 fps |
| 200 节点 | 框选全部再整体拖                | ≥45 fps |

同时记录：

- 松手到节点定住的延迟（应 ≤1 帧）
- 拖动中有没有 >200ms 长任务（有 → 缺陷，附 `window.__long`）
- 节点数从 10 涨到 200 时帧率下降的曲线

## P2 · 缩放与平移

⌘+滚轮连续缩放 3 秒、滚轮平移 3 秒、缩到下限 35%、放到上限 220%。
**200 节点在 35%（全部节点都在视口内）是最坏情况，必测。**

## P3 · 长列表

| 场景                | 测什么                     | PASS              |
| ------------------- | -------------------------- | ----------------- |
| 1000 条工作流首页   | 首屏渲染时间               | ≤1.5s             |
| 同上                | 滚动 3 秒帧率              | ≥55 fps           |
| 翻页                | 点「下一页」到列表更新     | ≤500ms 且有中间态 |
| 连点「下一页」10 次 | 跳页是否错乱、请求是否打架 | 顺序正确          |
| 500+ 事件的运行     | 事件流渲染时间与滚动帧率   | ≤2s / ≥50 fps     |

事件流特别注意：一页 200 条会**连续翻到 25 页**（上限 5000）。
测 1000+ 事件的运行，看首次点开多久、期间界面能不能操作。

## P4 · 响应反馈

测每个操作「点击 → 第一个可见变化」的毫秒数，并确认中间态：

| 操作               | 中间态应该是            |
| ------------------ | ----------------------- |
| 新建工作流         | 按钮 loading            |
| 保存草稿           | 按钮 loading + 文字变化 |
| 发布版本           | 按钮 loading            |
| 开始运行           | 按钮禁用                |
| 版本抽屉选一个版本 | 「正在读取版本…」       |
| 切换运行记录       | 列表清空 + 重新加载     |
| 预览产物           | 「正在读取…」           |
| 模型「测试连通性」 | 「测试中…」             |
| 环境「重新检查」   | 「检查中」              |
| 主管 AI 发送       | 「正在想…」+ 5 秒后计时 |

```js
(() => {
  const t0 = performance.now();
  const ob = new MutationObserver(() => {
    console.log('[首次变化]', Math.round(performance.now() - t0), 'ms');
    ob.disconnect();
  });
  ob.observe(document.querySelector('main'), {
    subtree: true,
    childList: true,
    characterData: true,
  });
})();
```

判据见总纲 §3.5.5。**没有中间态且 >1s → 缺陷。**

## P5 · 手快会不会出事（重入）

100ms 间隔连点 5 次，每条都看网络面板确认**实际发了几次请求**：

| 操作                | 期望                      |
| ------------------- | ------------------------- |
| 新建工作流          | 只建出 **1** 条           |
| 保存草稿            | 只提交一次，不出 rev 冲突 |
| 发布版本            | 只发布一个版本            |
| 开始运行            | 只起一次运行              |
| 审批「批准」        | 只决定一次                |
| MCP 确认「批准」    | 只决定一次                |
| 模型「测试连通性」  | 不叠加请求                |
| 快速切 5 条运行记录 | 事件不串台                |
| 快速切筛选 chips    | 最终显示与最后选的一致    |

## P6 · 轮询与定时器

运行中每 1200ms 拉事件与列表；主管 AI 等待时每秒计时；
MCP 确认卡每 1200ms 轮询；审批横幅每秒 tick。

1. 打开运行中的记录看 30 秒 → 请求应**匀速**，不该越来越密
2. 快速在 5 条运行间切换 → 之后仍是 1 次/1.2s（定时器叠加会变 5 次）
3. 离开执行记录页 → `run_events` 应停止
4. 切后台 5 分钟回来 → 有没有堆积爆发
5. MCP 确认卡在每屏都轮询 → 确认没在某屏叠加

## P7 · 内存

概览 ↔ 编辑器 ↔ 执行记录 来回 20 次，每 5 次记一次：

```js
performance.memory &&
  console.log('[内存]', Math.round(performance.memory.usedJSHeapSize / 1048576), 'MB');
```

增长 >100MB 且手动 GC 后不回落 → 缺陷（多半是定时器/订阅没清）。

## P8 · 输入不掉字

快速连续输入 30 个字符：概览搜索、执行记录搜索、脚本正文、
提示词分段正文（textarea 的 rows 会随行数变，重点看跳动）、
主管 AI 输入框、工作流改名。

**30 个字符只该发 1–2 次请求**（防抖生效）。每字一次 → 缺陷。

# 第二副眼镜 · 混沌

## X1 · 恶意输入（每个输入框都过一遍）

| 代号 | 内容                                                        | 关注                       |
| ---- | ----------------------------------------------------------- | -------------------------- |
| I1   | 空 / 只有空格                                               | 是否 trim、是否当未填      |
| I2   | 10 万字符                                                   | 布局撑破、卡死、请求过大   |
| I3   | `<script>alert(1)</script>`、`<img src=x onerror=alert(1)>` | **绝不能弹窗**             |
| I4   | Emoji + 零宽 + RTL                                          | 截断、长度计算、方向混乱   |
| I5   | `../../../etc/passwd`、`/etc/passwd`                        | 工作目录、仓库根、产物路径 |
| I6   | `${input.x}`、`{{7*7}}`                                     | 是否被当变量展开           |
| I7   | `a"b'c\nd\te`                                               | 序列化、表格错行           |

覆盖：概览搜索 / 工作流改名 / 节点标题 / 节点配置七种控件 / 分组名 /
启动参数 / 工作目录 / 记忆搜索 / Agent 三个字段 / 提示词分组·名称·分段·新分段标题 /
模型五个字段 / 主管 AI 输入框。

重点：

- **数字框输入非数字**（上下文窗口填 `abc`、参数填 `1e999`、`-1`、小数）→
  要么拦住并说明，要么正确转换，不能静默变 NaN
- **JSON 控件输入坏 JSON** → 保留用户输入 + 提示，**绝不能清空**
- **列表 chips 输入后不回车直接点别处** → 应被添加（onBlur 也 add）
- **键值对的键留空** → 应被丢弃而不是产生空键

## X2 · 断网

断网后点这些，每个都要**明确报错**且**数据不丢**：

保存草稿（本地改动仍在、可重试）/ 发布版本（不产生半个版本）/
开始运行（**报错留在表单里，参数不丢**）/ 切换运行记录（已有列表不清空）/
预览产物 / 主管 AI 提问（空气泡被移除）/ 环境重新检查 /
记忆停用删除（**界面不能变了而后端没变**）/ 模型启停。

恢复网络后**不刷新页面**再点一次 → 应成功。必须刷新才恢复 → 记「无路可走」。

## X3 · 后端挂掉

Ctrl-C 掉 devserver：

1. 刷新每一屏 → 都要有可读错误，**不能白屏**
2. 特别看模型/Agent/提示词：`items === null`（读取中/失败）与空数组
   （确实没有）是两种含义，挂掉时不该显示「还没有 X」这种误导文案
3. 重启 devserver → 点刷新 → 应恢复，不需要重开页面

## X4 · 请求飞到一半

| 场景                             | 期望                           |
| -------------------------------- | ------------------------------ |
| 点保存后立刻刷新                 | beforeunload 拦截；不能存一半  |
| 点开始运行后立刻关对话框         | 要么起要么没起，不能有幽灵运行 |
| 打开版本 Diff 后立刻切另一个版本 | 显示的必须是最后选的（竞态）   |
| 预览大产物时立刻切 tab           | 回来不能显示上一个文件的内容   |
| 主管 AI 提问后立刻点取消         | 答案被丢弃，留「已取消」回执   |
| 主管 AI 提问后立刻关抽屉再打开   | 不能出现重复气泡               |
| 100ms 间隔快速切 3 条运行        | 事件不串台                     |

## X5 · 并发冲突（两个标签页）

这是产品的**核心安全网**（`baseRevision` 守卫），必须测：

1. 两个标签页打开同一条工作流的编辑器
2. A 拖节点 → 保存 → 成功（rev N+1）
3. B（还在 rev N）拖节点 → 保存
4. **期望**：B 报冲突错误，旁边出现「放弃本地改动」按钮
5. 点它 → B 回到服务端那份图，错误消失
6. B 刷新后重新编辑 → 能正常保存

另测：两页同时发布（只应产生一个新版本）、一页删工作流另一页还在它的编辑器上、
两页同时批准同一审批（只有一个成功）。

# 第三副眼镜 · 键盘与读屏

## K1 · 只用键盘走完主流程

**全程不碰鼠标**，卡住就停下记录：

| 序  | 任务                       | 卡住记什么                        |
| --- | -------------------------- | --------------------------------- |
| 1   | 新建工作流                 | 焦点到不了 / 回车不触发           |
| 2   | 改名                       | 改名要双击，键盘怎么进入          |
| 3   | 从节点库加一个节点到画布   | **拖拽是唯一入口的话 → 重大缺陷** |
| 4   | 打开节点配置弹层           | 双击是唯一入口的话怎么办          |
| 5   | 切 tab、填字段、保存       | tab 能否方向键切换                |
| 6   | 关弹层                     | Esc 有没有用；焦点回到哪          |
| 7   | 保存草稿、发布版本         | —                                 |
| 8   | 版本抽屉：选版本、导出     | 抽屉内能否 Tab 循环               |
| 9   | 运行表单：填参数、开始运行 | —                                 |
| 10  | 执行记录：选运行、切 tab   | 运行条目是 button，应该可达       |
| 11  | 处理一次审批               | —                                 |

**第 3 步是重点**：节点库条目是 `role="button" tabIndex={0}` 的 div，
实际功能是 HTML5 拖放。键盘按回车会怎样？什么都不发生的话，
「往画布加节点」这个核心功能对键盘用户完全不可用 → 严重。

## K2 · 焦点

```js
(() => {
  const 可聚焦 = [
    ...document.querySelectorAll(
      'a[href],button:not([disabled]),input:not([disabled]),select:not([disabled]),textarea:not([disabled]),[tabindex]:not([tabindex="-1"])',
    ),
  ];
  console.table(
    可聚焦.map((el, i) => ({
      序: i + 1,
      标签: el.tagName,
      可访问名: el.getAttribute('aria-label') || el.textContent?.trim().slice(0, 24) || '(无名)',
      可见: el.getBoundingClientRect().width > 0,

```

- **任何「(无名)」都是缺陷**：读屏只会念「按钮」
- 焦点环要与 hover 效果**不同**，且在深色底上对比度够
- Tab 顺序要符合视觉顺序（跳来跳去 → 缺陷）
- 概览页隐藏的 `input[type=file]`（`.sr-only`）：焦点走到它时
  **必须看得出焦点在哪**，否则像凭空消失一格

## K5 · 无障碍标注

每屏一个 `<h1>`、标题不跳级、地标有 `aria-label`、
tablist/tab/aria-selected、权限三卡是 `role="radiogroup"` + 真 radio、

## K6 · 动态播报

保存失败 / 必填未填 / 运行状态变化 / 翻页 / 主管 AI 回答到达 /
**MCP 确认卡弹出**（它是打断性的，听不到就会让它超时＝拒绝）/ 审批横幅出现。

## K7 · 对比度与缩放

正文 ≥4.5:1、大字 ≥3:1、控件边框 ≥3:1。抽查每屏 ≥8 处。
浏览器缩放 200% / 50%、只放大文字 200%、系统「减少动态效果」。

---

## 收尾

跑完检查三件事，任一不成立都是阻塞级：

1. 应用还能正常打开、列表还在
2. `window.__err` 里没有未捕获错误
3. 数据库没有被写进非法数据

然后**重建数据库**再交给 B3。

## 你的报告要多两样东西

1. **`metrics.json`**：原始数字，不要只写结论

```json
{
  "画布拖动": {
    "10节点": { "平均帧率": 60, "最长帧ms": 22, "掉帧占比": "1%" },
    "200节点": { "平均帧率": 48, "最长帧ms": 96, "掉帧占比": "12%" }
  },
  "响应时长ms": { "新建工作流": 180, "发布版本": 640, "预览产物": 1200 },
  "长任务": [{ "时长": 260, "发生在": "拖动 200 节点画布" }],
```

> 拖动 200 节点画布时平均 48 fps、最长单帧 96ms、掉帧占比 12%，
> 期间出现一次 260ms 长任务。10 节点时为 60 fps。体感：明显一顿一顿。
