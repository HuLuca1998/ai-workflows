# 07 · 启动表单与 Dry Run

点编辑器工具栏的「运行」打开，660px 对话框。图纸里就是这个尺寸。

核心承诺：**启动表单由入口节点的输入 Schema 自动生成**（字段不写死），
**依赖检查没过就拦住运行**（明知跑不通还让它跑，用户拿到的是一个
跑到一半失败的运行和一堆已经产生的副作用）。

## 元素清单

| #   | 元素           | 内容                                                                 | 能点吗     |
| --- | -------------- | -------------------------------------------------------------------- | ---------- |
| 1   | 头部标题       | 「运行 · <工作流名>」                                                | 纯展示     |
| 2   | 头部副文本     | 「启动表单由入口节点的输入 Schema 自动生成」                         | 纯展示     |
| 3   | 关闭           | `aria-label="关闭"`                                                  | 应可点     |
| 4   | 运行版本分段器 | 「草稿 revN」+ 每个已发布版本一个按钮                                | 应可点     |
| 5   | 版本说明       | 选草稿与选版本时**两句不同的话**（见 LAU-04）                        | 纯展示     |
| 6   | 参数字段       | 由入口 Schema 生成；必填带 `*`                                       | 应可输入   |
| 7   | 无参数时       | 「这个工作流不需要启动参数。」                                       | 纯展示     |

## 用例

### LAU-01 · 打开表单，字段由 Schema 生成

- 类型：功能（**核心承诺**）
- 前置：一条工作流的 entry 节点配了 inputSchema，含：
  - `who`：字符串，必填，标题「打招呼的对象」
  - `greeting`：字符串，选填，默认「你好」
  - `count`：整数，带 min/max
  - `mode`：枚举
  - `dryRun`：布尔
- 操作：点工具栏「运行」
- 预期：
  1. 对话框宽 660px，`role="dialog"`，可访问名「运行 <工作流名>」
  2. 五个字段都渲染出来
  3. **标签用的是 Schema 里的 title**（「打招呼的对象」而不是 `who`）
  4. 必填的带 `*`，且**星号不进无障碍名**（可访问名是「打招呼的对象」不是「打招呼的对象 *」）
  5. 控件类型正确：
     - 字符串 → text
     - 整数 → number，且带 `min`/`max` 属性
     - 枚举 → select，首项是「请选择」
     - 布尔 → checkbox
  6. 有默认值的字段**预填了默认值**（`greeting` 里是「你好」）
- 失败判定：全渲染成文本框（丢掉类型的代价不是难看，是错——
  整数字段拿到「不是数字」照样能启动，后续节点拿到的参数是坏的）

### LAU-02 · 没有入口 Schema 时

- 类型：边界
- 前置：entry 节点没有配 inputSchema，或 properties 为空
- 预期：显示「这个工作流不需要启动参数。」，不显示空的字段区
- 失败判定：显示一个空白区域

### LAU-03 · 必填校验

- 类型：功能
- 操作：清空必填字段 → 点「开始运行」
- 预期：
  1. **不发起运行**
  2. 该字段出现红框（`aria-invalid` + `data-missing="true"`）
  3. 字段下方出现「必填项，请填写」
  4. 对话框不关闭，其他字段的值不丢
- 失败判定：只有红框没有文字（读屏用户完全不知道为什么点了没反应）

### LAU-04 · 布尔字段的 false 也算填了

- 类型：边界
- 前置：一个**必填的布尔字段**
- 操作：不勾选它（值是 false）→ 点「开始运行」
- 预期：**不报「必填项」**（用 trim 判空会把 false 当成没填）
- 失败判定：勾上才能运行

### LAU-05 · 版本选择

- 类型：功能
- 前置：已发布 v1、v2
- 操作：
  1. 看默认选中的是哪个
  2. 点「v1」
  3. 点「草稿 revN」
- 预期：
  1. 默认选中「草稿 revN」
  2. 选草稿时说明是「草稿会随编辑变化；运行记录里保存的是启动那一刻的修订号」
  3. 选版本时说明是「已发布版本不可变，这次运行会一直引用它」
  4. 选中的按钮有 `data-active="true"`
  5. **切换版本会重新跑一次 Dry Run**（检查结果可能不同）
- 失败判定：两种说明是同一句；切版本不重新检查

### LAU-06 · Dry Run 在打开时就跑

- 类型：功能
- 操作：打开表单，立刻看检查区
- 预期：
  1. 右上角先显示「检查中…」
  2. 完成后显示「N 项通过 · M 项缺失」
  3. 每项一行：通过的是绿色对勾（`data-status="passed"`），
     缺失的是红色叉（`data-status="failed"`）
  4. 每行文案是「<名称> · <详情>」
  5. **只列真的查过的项**（不列没查过的）
- 失败判定：要点某个按钮才开始检查；或列出一堆与这条工作流无关的检查

### LAU-07 · 检查未通过时拦住运行

- 类型：功能 / 安全（**核心承诺**）
- 前置：一条用到未安装工具的工作流（例如引用了不存在的解释器），
  或含尚未实现的节点类型
- 操作：打开表单
- 预期：
  1. 检查区有失败项，说明**缺什么**
  2. 底部显示「依赖检查未通过，先解决上面标出的问题」
  3. 「开始运行」**禁用**
- 失败判定：能点开始运行（用户会拿到一个跑到一半失败的运行 +
  已经产生的副作用）

### LAU-08 · 尚未实现的节点类型在 Dry Run 阶段就报

- 类型：功能 / 可解释性
- 操作：搭一条含尚未实现节点类型的工作流（如果还有的话），打开运行表单
- 预期：检查项里明确写「尚未实现」，而不是让它跑起来假装成功
- 说明：M3 之后 AI 四类节点已实现。如果所有类型都实现了，
  这一条记为「不适用」，但要说明你是怎么确认的。

### LAU-09 · 工作目录

- 类型：功能 / 边界
- 操作：
  1. 看占位文字
  2. 留空直接运行
  3. 填一个自定义目录再运行
  4. 填 `/etc` 或 `../../..`
- 预期：
  1. 占位显示引擎给的**默认目录的真实路径**（不是「正在读取默认目录…」卡住不动）
  2. 留空时用默认目录，运行详情里能看到它
  3. 自定义目录生效，运行详情显示的是它
  4. 非法路径的行为记录下来（**抄送 [B3 剧本 S8](personas/B3-安全与可解释性.md)**）
  5. 改工作目录会**重新跑 Dry Run**
- 失败判定：占位一直是「正在读取默认目录…」

### LAU-10 · 开始运行

- 类型：功能
- 操作：填好必填字段 → 点「开始运行」
- 预期：
  1. 按钮禁用（防重复）
  2. 成功后对话框关闭
  3. **跳到 `/runs?run=<新 runId>`**，并直接展开那次运行
  4. 执行记录里能看到刚才填的参数（启动参数区）
- 失败判定：运行起来了但没跳转；或跳了但没选中那条

### LAU-11 · 参数类型真的带下去了

- 类型：功能 / 可解释性
- 操作：
  1. number 字段填 `3`，boolean 勾上，text 填「你好」
  2. 运行后去执行记录看「启动参数」
- 预期：
  1. 显示 `count=3`（不是 `count="3"`）
  2. 布尔显示 `dryRun=true`
  3. 脚本里 `${input.count} + 1` 得到 4 而不是 `31`
     （在脚本节点里 `echo $((${input.count} + 1))` 验证）
- 失败判定：数字变成了字符串（那只有跑到那一行才会暴露）

### LAU-12 · 启动失败时留在表单里

- 类型：边界
- 操作：断网 → 点「开始运行」
- 预期：
  1. 对话框**不关闭**
  2. 显示错误（`role="alert"`）
  3. **填的参数全都还在**
  4. 恢复网络后再点一次能成功
- 失败判定：对话框关了，参数没了，得重填一遍

### LAU-13 · 连点「开始运行」

- 类型：边界
- 操作：100ms 间隔连点 5 次
- 预期：只起**一次**运行（网络面板里 `run_start` 只发一次）
- 失败判定：起了多条运行

### LAU-14 · 关闭表单的三种方式

- 类型：功能
- 操作：点「取消」/ 点遮罩 / 点右上角关闭
- 预期：三种都关闭，且**不起运行**
- 失败判定：点遮罩关不掉；或关闭时误触发运行

### LAU-15 · 数字字段的边界

- 类型：边界
- 前置：一个带 `minimum: 1`、`maximum: 100` 的整数字段
- 操作：依次输入 `0`、`101`、`-1`、`1e999`、`abc`、`1.5`、留空
- 预期：
  1. 输入框有 `min`/`max` 属性（浏览器会给原生提示）
  2. 超范围的值：记录实际行为（是拦住还是发下去让引擎拒）
  3. `abc` 不能变成 `NaN` 发下去
  4. 留空且非必填时，该参数**不出现在启动参数里**（不是空字符串）
- 失败判定：`NaN` 被当成参数发出去

### LAU-16 · 枚举字段没选时

- 类型：边界
- 操作：枚举字段保持「请选择」→ 运行
- 预期：
  1. 必填时报「必填项，请填写」
  2. 非必填时该参数不出现在启动参数里
- 失败判定：把「请选择」这个字面量当成值发下去

### LAU-17 · 长表单在矮窗口下

- 类型：边界
- 操作：窗口高度调到 500px，打开一个有 8+ 个参数的工作流
- 预期：内容可滚动，底部「开始运行」按钮**够得着**
- 失败判定：按钮被挤出屏幕

### LAU-18 · 「开始运行」的可发现性

- 类型：体验
- 操作：用[总纲 §3.5.3](README.md) 的脚本量「开始运行」按钮的位置
- 预期：在对话框内首屏可见，不需要滚动
- 说明：检查项多的时候（十几项）表单会变长——量一下那时的情况。

### LAU-19 · 三问清点

- 类型：体验
- 操作：对这些做三问：
  失败的检查项（#11——用户想点它看**怎么装**）、
  工作目录占位里的路径（想点它选目录或复制）、
  版本分段器上的 vN（想点它看那个版本的图）
- 重点：**失败的检查项**。它告诉你「缺 git」，
  用户的下一个问题一定是「那我怎么装」。
  点得动吗？有没有给命令？还是要自己跑到「设置与环境」去找？
