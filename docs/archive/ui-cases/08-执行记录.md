# 08 · 执行记录

路由 `/runs`，可带 `?run=<id>`。图纸「03 执行记录」。

三栏：**308px 运行列表 · 232px 节点进度 · 详情**。

审批与失败恢复见 [09](09-审批与失败恢复.md)。

> **这一屏有一批已知的图纸差异**（节点行不能点、缺分组标题行、
> 缺时长与百分比、事件卡缺输入输出块等），完整清单在
> [F1 剧本 B4](personas/F1-界面与体验.md)。测到时按那张表复核，不要重复报。

### 事件流 tab

每条事件：时间 · 类别（审批/节点/AI/运行）· 类型 · 节点名 · 摘要 + 左侧色条。
底部常驻：「Secret 值在写入事件存储前已脱敏，界面不提供绕过查看」。

### 产物 tab

每条产物：类型图标 + 文件名 + 「<大小> · <节点id>」+「预览」按钮。
底部显示产物根目录。空态：「这次运行还没有产物。脚本的输出与生成的文件会出现在这里。」

### 对话 tab

当前显示：「对话视图要等 AI 节点接上 ACP（M3）。现在这次运行还没有 AI 消息。」
—— **M3 已交付，这句话是否过期在 RUN-22 判定。**

## 用例

### RUN-01 · 空态

- 类型：功能
- 前置：一次运行都没有
- 预期：
  1. 左栏显示空态那句话（一字不差）
  2. 中栏显示「运行的节点会在这里逐个亮起。」
  3. 右栏显示「选一次运行，这里会显示它的完整记录。」
- 失败判定：三栏都是空白

### RUN-02 · 从编辑器运行后直接展开那一次

- 类型：功能
- 操作：在编辑器点「运行」→ 填参数 → 开始运行
- 预期：
  1. 跳到 `/runs?run=<id>`
  2. **那一条自动被选中**（`data-selected`）
  3. 右栏显示它的详情
- 失败判定：跳过来但没选中，用户要自己在列表里找

### RUN-03 · 运行中的记录实时更新

- 类型：功能
- 前置：一条会跑几十秒的工作流（脚本里 `sleep 30`）
- 操作：起一次运行，停在这一屏观察
- 预期：
  1. 状态徽章从「排队中」→「运行中」
  2. 节点逐个从「执行中」变成「完成」
  3. 事件条数持续增加
  4. 进度条前进
  5. 轮询间隔约 **1.2 秒**（网络面板确认）
  6. 跑完后**停止轮询**（不再发 `run_events`）
- 失败判定：要手动点刷新才更新；跑完了还在轮询

### RUN-04 · 离开这一屏后停止轮询

- 类型：性能 / 边界
- 操作：选中一条运行中的记录 → 切到「记忆」屏 → 看网络面板
- 预期：`run_events` 与 `run_list` 停止
- 失败判定：切走了还在轮询（详见 [F2 剧本 P6](personas/F2-交互健壮性.md)）

### RUN-05 · 分组：进行中与历史

- 类型：功能
- 前置：同时有进行中与已结束的运行
- 预期：
  1. 上面一组标题「并行进行中 · N」，带**脉冲圆点**
  2. 下面一组标题「历史 · N」
  3. 两个数字与各自组里的条数一致
  4. 「进行中」包括 created / queued / running / **waiting_approval**
     （等待审批也算没结束，它只是在等人）
- 失败判定：等待审批的被归到历史里

### RUN-06 · 四个筛选 chip

- 类型：功能
- 操作：依次点 全部 / 运行中 / 待审批 / 失败
- 预期：
  1. 每次都回到第 1 页
  2. 选中的 chip 有 `data-active="true"`
  3. 列表内容与语义一致
- 失败判定：筛选后停在原来的页

### RUN-07 · 搜索

- 类型：功能
- 操作：
  1. 输入工作流名的一部分，不按回车，等 1 秒
  2. 输入一个完整的 Run ID
- 预期：
  1. 输入即搜（300ms 防抖），与概览页**同一套交互**
  2. 能按 Run ID 搜到
  3. 搜索发给后端（不是只过滤当前页）
- 失败判定：必须回车才搜（与概览页不一致，用户每换一屏都要重新试）

### RUN-08 · 切换运行时事件不串台

- 类型：边界
- 操作：100ms 间隔快速点三条不同的运行
- 预期：
  1. 每次切换先**清空**事件再拉新的
  2. 最终显示的是最后点的那条的事件
  3. 不出现别的运行的事件混进来
- 失败判定：事件列表里混着两条运行的记录

### RUN-09 · 节点进度与事件流一致

- 类型：可解释性
- 操作：选一条跑完的运行，对比中栏与事件流
- 预期：
  1. 节点顺序 = 事件里第一次出现的顺序
  2. 每个节点的状态 = 它最后一条事件对应的状态
  3. 「N 个节点已完成」= 事件里 `node.succeeded` 的**去重节点数**
  4. 显示的是**节点标题**不是 nodeId
- 失败判定：数字对不上（详见 [B3 剧本 V4](personas/B3-安全与可解释性.md)）

### RUN-10 · 节点显示的是当时的名字

- 类型：可解释性 / 边界
- 操作：
  1. 跑完一次
  2. 回编辑器把某个节点改名并保存
  3. 回执行记录看那条运行
- 预期：显示的仍是**跑的时候**那个名字（事件里记的是当时的标题）
- 失败判定：跟着草稿变了（历史就不可解释了）

### RUN-11 · 节点行能不能点（⚠️ 重点）

- 类型：体验 / 图纸符合性
- 操作：
  1. 鼠标悬停在中栏某个节点行上——光标变手型了吗？有 hover 反馈吗？
  2. 点它
  3. 用无障碍树看它是不是 button
  4. 用 Tab 能不能走到它
- 预期（**按图纸**）：可点，点了能看到这个节点的详情
- 当前实现：纯展示的 div，点不动
- 判定：
  - 仍然点不动 → 复核 [F1 剧本 B4](personas/F1-界面与体验.md) 差异 #1，
    并按三问记录「用户想看什么 / 现在能看到什么」
  - 已经能点 → 验证点完给的是不是用户要的：
    这个节点的**输入、输出、耗时、日志、失败原因**
- 说明：这是用户明确提过的问题。
  **现在想看单个节点的执行信息，只能去事件流里人工找带那个节点名的几条。**
  在报告里写清这条绕行路径有多难走（要翻多少条事件）。

### RUN-12 · 事件流

- 类型：功能
- 操作：切到「事件流」tab
- 预期：
  1. 每条事件显示：时间（时分秒）· 类别 · 类型 · 节点名 · 摘要
  2. 类别是中文：审批 / 节点 / AI / 运行
  3. 左侧色条按类别着色（`data-kind`）
  4. 底部常驻脱敏说明
  5. 右上角「N 条事件」与实际条数一致
  6. 空运行显示「这次运行还没有事件。」
- 失败判定：类别显示英文；条数对不上

### RUN-13 · 超过 200 条事件要全部拉完

- 类型：边界 / 可解释性
- 前置：一条产生 200+ 条事件的运行（30 个节点的工作流）
- 操作：打开它的事件流
- 预期：
  1. 显示的是**全部**条数（如 217），不是停在 200
  2. 最后一条是运行的终态事件（`run.succeeded` / `run.failed`）
- 失败判定：停在 200 条——缺的正是「它最后怎么结束的」

### RUN-14 · 产物列表

- 类型：功能
- 前置：一条产出了文件的运行
- 操作：切到「产物」tab
- 预期：
  1. 每条显示：类型图标 + 文件名 + 「<大小> · <节点id>」+「预览」按钮
  2. 图标按类型区分：diff / report / log / 其他
  3. 底部显示产物根目录
  4. 没有产物时显示那句空态
- 失败判定：大小显示成 `NaN B`

### RUN-15 · 预览产物

- 类型：功能
- 操作：
  1. 点某个文本产物的「预览」
  2. 再点一次
  3. 点另一个产物的「预览」
- 预期：
  1. 就地展开（不是弹层），显示内容，`aria-expanded="true"`
  2. 再点收起
  3. **同时只展开一条**（点第二条时第一条收起）
  4. 展开时先显示「正在读取…」
- 失败判定：两条同时展开；或展开的是上一个文件的内容

### RUN-16 · 二进制产物与截断

- 类型：边界
- 前置：一条产出了二进制文件（如图片）和一个大文本文件的运行
- 操作：分别预览
- 预期：
  1. 二进制显示「这是二进制文件（<大小>），没法在这里预览。」
     （**不显示乱码**——那会让用户以为文件坏了）
  2. 大文本显示前一部分，末尾提示
     「只显示了前一部分，完整内容共 <大小>。」
- 失败判定：二进制渲染成乱码

### RUN-17 · 取消运行

- 类型：功能
- 前置：一条正在跑的运行（脚本里 `sleep 60`）
- 操作：点右栏的「取消运行」
- 预期：
  1. 按钮只在进行中的运行上出现
  2. 点完之后状态变成「已取消」
  3. 事件流里出现取消相关的事件
  4. 节点进度里，正在跑的那个节点的最终状态可解释
     （不能停在「执行中」永远不动）
  5. 已经跑完的节点仍显示「完成」
- 失败判定：点了没反应；或状态一直不变

### RUN-18 · 取消已结束的运行

- 类型：边界
- 操作：选一条已成功的运行
- 预期：**没有**「取消运行」按钮
- 失败判定：按钮还在，点了报错

### RUN-19 · 详情头部的元信息

- 类型：功能 / 可解释性
- 操作：看右栏头部
- 预期：
  1. 工作流名 + 状态徽章
  2. 「启动参数」+ 每个参数一个 chip，形如 `who=世界`
  3. 开始时间（`zh-CN` 24 小时制）
  4. Run ID（完整）
  5. 工作目录（如果有）
- 失败判定：参数显示成 `[object Object]`；时间显示 `Invalid Date`

### RUN-20 · 分页

- 类型：功能 / 边界
- 前置：≥60 条运行
- 预期：每页 50 条，范围文字正确，首末页按钮禁用
- 补充：量一下**分页控件需要滚动多少才看得见**
  （左栏是独立滚动区，与概览页的情况不同）

### RUN-21 · 并行运行互不影响

- 类型：功能 / 可解释性
- 操作：同一条工作流用不同参数同时起两次
- 预期：
  1. 两条都出现在「并行进行中」
  2. 各自的启动参数不同
  3. **工作目录不同**
  4. 各自的事件流独立，互不混淆
  5. 底部那句「同一工作流可用不同参数并行运行，环境快照互不影响」是真的
- 失败判定：两条运行的产物写到了同一个目录

### RUN-22 · 「对话」tab 的文案是否过期

- 类型：可解释性
- 操作：切到「对话」tab
- 当前文案：「对话视图要等 AI 节点接上 ACP（M3）。现在这次运行还没有 AI 消息。」
- 判定：
  - **M3 已交付**（`docs/ROADMAP.md`），AI 四类节点已走真实 ACP 会话
  - 跑一条含 AI 节点的工作流（**用 `acp.codex`**，见 CLAUDE.md 纪律），
    看这个 tab 显示什么
  - 仍显示那句话 → **文案过期，是缺陷**
  - 显示了对话内容 → 验证内容是否正确（消息顺序、角色区分）
- 失败判定：跑了 AI 节点仍说「还没有 AI 消息」

### RUN-23 · 三栏宽度

- 类型：图纸符合性
- 操作：量三栏宽度
- 预期：左 308px、中 232px（右栏自适应）
- 失败判定：与图纸不符（交 F1 记录）

### RUN-24 · 三问清点（这一屏是重点）

- 类型：体验
- 操作：对元素清单里标「待验证」的全部做三问，交完整清点表：
  当前节点文字（#13）、**节点行（#14）**、工作流名（#16）、
  启动参数 chip（#19）、开始时间（#20）、**Run ID（#21）**、
  **工作目录（#22）**、事件条目、事件里的节点名、产物文件名、产物大小
- 重点问题：
  1. **Run ID 能复制吗**？用户要把它贴到 issue 里
  2. **工作目录能复制/打开吗**？用户要去那里看文件
  3. **事件条目能展开吗**？摘要不够时想看完整 payload
  4. **产物文件名能点吗**？（现在只有右侧的「预览」按钮可点）
  5. **工作流名能点吗**？用户想跳回去看这条工作流的图
