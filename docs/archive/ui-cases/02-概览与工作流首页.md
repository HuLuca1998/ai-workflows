# 02 · 概览与工作流首页

路由 `/`。这是打开应用的第一屏，也是找到一切的入口。

图纸「01 工作流首页」。

## 元素清单

**「能点吗」一列是你要去验证的，不是抄答案。**

### 头部

| #   | 元素           | 内容                                              | 能点吗   | 点了应该怎样                     |
| --- | -------------- | ------------------------------------------------- | -------- | -------------------------------- |
| 1   | kicker         | 「本地优先 · N 个工作流」（N 是**总数**不是本页） | 纯展示   | —                                |
| 2   | 标题           | 「工作流」                                        | 纯展示   | —                                |
| 3   | 搜索框         | 放大镜图标 + 占位「搜索工作流、运行或产物」       | 应可输入 | 输入即搜（300ms 防抖），回车立刻 |
| 4   | 「导入」按钮   | 次级按钮                                          | 应可点   | 打开文件选择器                   |
| 5   | 隐藏文件输入   | `.sr-only`，`aria-label="导入工作流文件"`         | 键盘可达 | 只接受 `application/json,.json`  |
| 6   | 「新建工作流」 | 主按钮，`ph-plus` 图标                            | 应可点   | 建一条并跳进它的编辑器           |

### 统计区（`role="region" aria-label="概览统计"`）

| #   | 卡            | 主数字             | 副文本               | 能点吗     |
| --- | ------------- | ------------------ | -------------------- | ---------- |
| 7   | 等待审批      | 数字（**强调色**） | 可能有提示文本       | **待验证** |
| 8   | 今日运行      | 数字               | 「N 成功」（成功色） | **待验证** |
| 9   | Token 用量    | 当前应是「—」      | 「本周」             | **待验证** |
| 10  | 活跃 worktree | 数字               | 「占用 N MB」        | **待验证** |

> 四张卡都是「有数字、有名字」的东西，用户会想点它们下钻。
> 按[总纲 §3.6](README.md) 做三问。

### 三种空/错状态

| #   | 状态       | 触发条件         | 内容                                                          |
| --- | ---------- | ---------------- | ------------------------------------------------------------- |
| 21  | 首次空态   | 一条工作流都没有 | 图标 + 「还没有工作流」+ 说明 + 模板按钮 + 「新建空白工作流」 |
| 22  | 筛选无结果 | 加了条件后为空   | 表格里一行「当前筛选下没有工作流」+「清除筛选」链接           |

| 24  | 导入失败   | 文件不合法       | 「导入失败：<原因>」（`role="alert"`）                        |
| 25  | 加载中     | 首次拉取         | 「正在读取…」                                                 |

## 用例

### OVW-01 · 全新库进来是首次空态，不是空表格

- 类型：功能 / 体验
- 前置：全新数据库
- 操作：打开 `/`
- 预期：
  1. 显示空态：图标 `ph-flow-arrow`、标题「还没有工作流」
  2. 说明文字：「从模板开始，或新建一个空工作流再从左侧拖入入口节点。」
  3. 至少一个模板按钮，名称「GitHub Issue 修复」，
     副文本「读 Issue → 分析 → 审批 → worktree → 修复 → 审查 → 决策 → PR」
  4. 底部有主按钮「新建空白工作流」
  5. **不显示表格**，也**不显示分页**
  6. kicker 显示「本地优先 · 0 个工作流」
- 失败判定：显示了一个只有表头的空表格；或显示「当前筛选下没有工作流」
  （那是另一种状态，混了就是缺陷）

### OVW-02 · 从模板建一条工作流

- 类型：功能
- 前置：OVW-01 的空态
- 操作：点「GitHub Issue 修复」模板按钮
- 预期：
  1. 按钮进入禁用/加载态（防重复）
  2. 建成后**直接跳进编辑器** `/editor/<新 id>`
  3. 画布上有模板的节点（不是空画布）
  4. 工具栏名称是「GitHub Issue 修复」
  5. 校验状态显示「校验通过」（模板应当是合法的）
- 失败判定：跳到编辑器但画布是空的；或停在列表页不跳转

### OVW-03 · 新建空白工作流

- 类型：功能
- 操作：点「新建工作流」（右上角主按钮）
- 预期：
  1. 按钮显示加载态
  2. 跳进 `/editor/<新 id>`
  3. 名称形如「未命名工作流 N」（由引擎编号，不是前端按页内条数编的）
  4. 画布空，显示提示「从左侧拖入入口节点」
- 失败判定：名字用了页内条数（建第 51 条时叫「未命名工作流 1」就是这个 bug）

### OVW-04 · 连点「新建工作流」只建出一条

- 类型：边界
- 操作：100ms 间隔连点「新建工作流」5 次
- 预期：
  1. 只建出 **1** 条工作流
  2. 网络面板里 `workflow_create` 只发了 1 次
- 失败判定：建出多条（重入保护失效）

### OVW-05 · 搜索是输入即搜，300ms 防抖

- 类型：功能 / 体验
- 前置：至少 3 条工作流，其中一条名字含「打招呼」
- 操作：
  1. 在搜索框逐字输入「打招呼」，**不按回车**
  2. 停手等 1 秒
- 预期：
  1. 输入框立刻显示所键入的字（显示不防抖）
  2. 停手约 300ms 后列表自动刷新，只剩名字匹配的行
  3. 网络面板里 `workflow_list` **只发了 1–2 次**，不是每键一次
  4. kicker 与分页的总数**跟着筛选变**
- 失败判定：必须按回车才搜；每输入一个字符发一次请求；总数没变

### OVW-06 · 回车立刻搜，且连按两次不重复请求

- 类型：功能 / 边界
- 操作：输入「打招呼」后立刻按回车，再按一次回车
- 预期：
  1. 第一次回车立刻发请求（不等 300ms）
  2. 第二次回车**不再发**（同一个词已经搜过）
- 失败判定：连按回车打出两次请求

### OVW-07 · 搜索无结果时给的是「筛选无结果」而不是「还没有工作流」

- 类型：功能 / 体验
- 操作：搜索一个肯定不存在的词，如「zzzz不存在zzzz」
- 预期：
  1. 表格仍在（表头可见）
  2. 表格内一行：「当前筛选下没有工作流」
  3. 同行有「清除筛选」链接
  4. **不显示**「还没有工作流」那套空态与模板
- 失败判定：显示了首次空态（用户会以为数据丢了）

### OVW-08 · 「清除筛选」把条件清到后端

- 类型：功能 / 边界
- 前置：OVW-07 的状态（搜索框里还有词）
- 操作：点「清除筛选」
- 预期：
  1. 搜索框清空
  2. 筛选 chip 回到「全部」
  3. 列表恢复完整（不是仍显示筛选后的那一页）
  4. 网络面板里发出的 `workflow_list` **不带 query 与 status 参数**
- 失败判定：只清了前端 state，列表还是筛过的

### OVW-09 · 四个筛选 chip 各自生效，且回到第一页

- 类型：功能 / 边界
- 前置：≥60 条工作流（能翻到第二页），其中有运行中/草稿/失败各若干
- 操作：
  1. 翻到第 2 页
  2. 点「失败」chip
  3. 依次点「运行中」「草稿」「全部」
- 预期：
  1. 点 chip 后**回到第 1 页**（不能停在第 2 页导致「筛完一条都没有」）
  2. 每个 chip 的选中态可见（`aria-selected="true"`）
  3. 列表内容与 chip 语义一致
  4. 分页总数跟着变
- 失败判定：筛选后仍停在第 2 页；chip 选中态不可见

### OVW-10 · 状态列显示的是最近一次运行，不是工作流自己

- 类型：功能 / 可解释性
- 前置：一条工作流跑过一次并失败
- 操作：看那一行
- 预期：
  1. 状态徽章是「失败」，不是「已创建」
  2. 徽章下方有运行状态文案，失败时还带「· <失败节点名>」
  3. 「最近一次运行」列显示「<时间> · <时长>」
  4. 从没跑过的行显示徽章「已创建」+ 该列「未运行」
- 失败判定：跑过三次的工作流仍显示「已创建 · 未运行 · 草稿」

### OVW-11 · 版本列跟着最近一次运行走

- 类型：可解释性 / 边界
- 前置：发布 v1 → 运行一次 → 再发布 v2、v3（不再运行）
- 操作：看那一行的「版本 · 触发」列
- 预期：显示 **v1**（那次运行引用的版本），后跟「· 手动」
- 失败判定：显示 v3（最新版本）——那与执行记录对不上

### OVW-12 · 行尾按钮：失败行是重试，其余是运行

- 类型：功能
- 操作：
  1. 找一条失败的工作流，看行尾图标，点它
  2. 返回，找一条正常的工作流，看行尾图标，点它
- 预期：
  1. 失败行的图标是 `ph-arrow-counter-clockwise`，
     `aria-label` 是「重试 <工作流名>」，点击去 `/runs/<runId>`
  2. 其余行是 `ph-play`，`aria-label` 是「运行 <工作流名>」，
     点击去 `/editor/<id>`
  3. **点行尾按钮不会同时触发整行点击**（不能跳两次）
- 失败判定：点按钮时整行的跳转也发生了（缺 `stopPropagation`）

### OVW-13 · 整行可点，进编辑器

- 类型：功能
- 操作：点某一行的名称区域
- 预期：
  1. 跳到 `/editor/<该行 id>`
  2. 鼠标悬停时行有 hover 反馈，光标是手型（`title="打开编辑器"`）
- 失败判定：只有名称文字能点、行的其他区域点不动

### OVW-14 · Token 用量显示「—」而不是 0

- 类型：可解释性
- 操作：看第三张统计卡
- 预期：主数字是「—」，副文本「本周」
- 说明：事件流里目前不记 token，显示 0 会被读成「这周没花钱」。
  如果显示了 0 → 缺陷；如果显示了真实数字 → 说明已经接上了，记录下来。

### OVW-15 · 统计卡数字与实际一致

- 类型：可解释性
- 操作：
  1. 记下「等待审批」的数字
  2. 去执行记录，筛「待审批」，数条数
  3. 记下「今日运行」，数今天的运行条数
- 预期：两两一致
- 失败判定：对不上（写清差了多少）

### OVW-16 · 分页：50 条一页

- 类型：功能 / 边界
- 前置：≥120 条工作流
- 操作：
  1. 数第一页的行数
  2. 点「下一页」
  3. 一直点到最后一页，再看「下一页」
  4. 在第一页看「上一页」
- 预期：
  1. 每页 50 行
  2. 范围文字形如「1 – 50 / 共 120 条」，翻页后变成「51 – 100 / 共 120 条」
  3. 最后一页的「下一页」禁用
  4. 第一页的「上一页」禁用
  5. 范围文字是 `role="status"`（翻页后读屏会播报）
- 失败判定：范围数字算错；到底了还能继续点

### OVW-17 · 分页控件要滚多远才看得见（可发现性）

- 类型：体验
- 前置：≥120 条工作流
- 操作：在 `/` 首屏（不滚动）跑[总纲 §3.5.3](README.md) 的脚本，量分页控件的位置
- 预期：需要滚动 **0 px**（首屏可见）
- 说明：**用户已明确反馈过这一条**：
  _「流程列表页面看不到翻页，需要往下滚动很远才能翻页」_。
  给出确切数字：需要滚动 N px、相当于 N 屏。
  需要滚动 > 1 屏 → **FAIL**，交 F1 记录。

### OVW-18 · 一条工作流都没有时不显示分页

- 类型：边界
- 前置：全新库
- 预期：分页控件**不出现**（总数 ≤ 一页时它只是噪音）
- 失败判定：显示了「1 – 0 / 共 0 条」

### OVW-19 · 导入一份合法的图

- 类型：功能
- 前置：先从某条工作流的版本抽屉导出一份 JSON
- 操作：
  1. 点「导入」
  2. 选那份 JSON
- 预期：
  1. 建出一条新工作流，名字是**文件名去掉 .json**
  2. 直接跳进它的编辑器
  3. 画布上的图与导出时一致（节点数、连线数相同）
- 失败判定：名字带着 `.json`；图不完整

### OVW-20 · 导入坏文件必须说清原因，且不动现有数据

- 类型：边界
- 操作：依次导入这些（每次都回到 `/` 重新点导入）：

  | 文件                    | 期望提示                                   |
  | ----------------------- | ------------------------------------------ |
  | 随便一段文本（非 JSON） | 「导入失败：不是合法的 JSON：…」           |
  | `{"a":1}`               | 「导入失败：不是有效的工作流图 —— …」      |
  | 缺 entry 节点的图       | 「导入失败：图存在 N 个错误，无法导入：…」 |
  | 有悬空边的图            | 同上                                       |
  | 有环的图                | 同上                                       |
  | 空文件                  | 明确提示                                   |

- 预期：
  1. 每次都显示 `role="alert"` 的「导入失败：<原因>」
  2. **原因具体到哪里不对**，不是一句「导入失败」
  3. 现有列表**没有变化**（没有建出半条工作流）
- 失败判定：静默失败；或建出了一条坏工作流

### OVW-21 · 选了文件又取消

- 类型：边界
- 操作：点「导入」，在文件选择器里按取消
- 预期：什么都不发生，不报错
- 失败判定：出现「导入失败」提示

### OVW-22 · 同一个文件连续导入两次

- 类型：边界
- 操作：导入某文件成功后回到 `/`，再导入同一个文件
- 预期：第二次仍然生效（建出第二条）
- 失败判定：第二次点了没反应（`input.value` 没清）

### OVW-23 · 后端挂掉时的表现

- 类型：边界
- 操作：停掉 devserver，刷新 `/`
- 预期：
  1. 显示「读取失败：<原因>」（`role="alert"`）
  2. **不显示**「还没有工作流」那套空态（那会误导用户以为数据没了）
  3. 页面不白屏，侧栏与标题栏仍在
- 失败判定：显示首次空态；或整页白屏

### OVW-24 · 三问清点

- 类型：体验
- 操作：对元素清单里标「待验证」的 7 项做三问，交清点表：
  四张统计卡（#7–10）、表头（#13）、状态徽章（#16）、
  最近一次运行（#17）、版本 Tag（#18）
- 记录：每一项「想不想点 / 点得动吗 / 点完给的是不是想要的」
- 说明：这些都是「有名字、有数据」的元素，用户天然会想下钻：
  点「等待审批 3」想看那 3 个是谁、点版本 Tag 想看那个版本的图。
  点不动的记「想点但点不动」，并评估有没有别的入口能到达。
