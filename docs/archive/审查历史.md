## 六条留下来的方法

### 1. 「绿着的测试守不住它宣称的东西」是一类独立缺陷

第 5 轮最值钱的发现：三个角色各自独立撞上同一件事——**五道守卫是假的**。
状态机门禁不读契约只比硬编码字面量；DTO 漂移守卫只认名字带 `Dto` 的结构体漏了 12 个；
禁用内部代号的正则只认三种写法，换行即绕过。

> 它绿着，给人「这类问题以后不会再有了」的保障，但保障的范围只覆盖了
> 恰好已经修掉的那几处的写法。**比没有测试更糟：没有测试至少不会有人以为它被守住了。**

判据：**给守卫本身写一条会让它变红的测试**。守卫不能证明自己会红，就不是守卫。
这条后来成了 [DEBT.md](../DEBT.md) 整份台账的方法论基础。

### 2. 要真的点，看不到就是 FAIL

不能因为「代码里写了所以应该对」判 PASS。第 5 轮用最硬的办法验「新增节点类型不改 UI 代码」——
往契约里加一个真节点类型、混入 9 种字段形状、一行 UI 代码不改，然后用真实浏览器看结果。
好消息是七种控件够用；坏消息是三张按类型穷举的表让节点根本拖不进画布，
而用户看到的是一句「节点配置不合法」——**他什么都还没填**。

### 3. 判定标准必须量化

模糊标准会被自己说服。当时定下、现在仍然有效的几条：

| 项           | 标准                                       |
| ------------ | ------------------------------------------ |
| 拖动帧率     | ≥55 fps，最长帧 ≤50ms                      |
| 主操作入口   | 滚动 0px 可见                              |
| 响应 >1s     | 必须有中间态且可取消                       |
| 可点元素三问 | 想不想点 / 点得动吗 / 点完给的是不是他要的 |

### 4. 一个会话一个角色

换角色开新会话。上一个角色的发现留在上下文里，会让下一个带着答案去找问题——
那正是漏检的来源。静态角色可并行，动态角色共享浏览器与数据库必须串行。

### 5. 真人自由使用能发现自动化测不到的

codex 以真人身份使用报出的问题，没有一条是单元测试能发现的：
刷新页面草稿直接消失、模型加载竞态导致按钮永久禁用、
执行记录列表里的 Secret 泄露、管理三屏「看得见但改不了」。

代价是它也会报不成立的问题（「登记 high 刷新变 medium」两轮都没能复现，
写了 e2e 往返测试压着，至今是绿的）。**报告不等于缺陷，每条都要自己复现一次。**

### 6. 自己犯的错也要记

第 5 轮复验时验证产物脱敏，第一次用了错的命令名（`run_artifactContent`），
拿到 400 却把空字符串当成「不含密钥」，差点得出反向结论。
用正确的 `run_artifact_content` 重测才看到真相——**产物预览确实在泄露明文**。

盘点 [DEBT.md](../DEBT.md) 时也发生过一次同类：差点把「eslint-disable 关的是不存在的规则」
列进台账，实测（写一个缺依赖的探针文件跑 oxlint）证伪了它。

**结论与验证手段不匹配时，先怀疑验证手段。**
